# DevLog — 2026-07-31

## 主线：行为路径自学习系统（Phase 1-3）

### 目标

构建基于 RAG 的自我进化系统：Agent 工具调用链作为"行为路径"存入向量库，新事件通过 embedding 语义检索召回历史相似任务，按贝叶斯置信度排序复用。用户反馈更新置信度，失败时 Critic LLM 分析原因生成规则。

### 新建模块

`wechat-ai-proactive`（第 9 个 Maven 子模块），依赖：common / session / document / tool / agent。

### Phase 1 — 核心闭环（上午）

**BehaviorPathService**（3 个入口）：

| 入口 | 时机 | 流程 |
|------|------|------|
| `retrieveAndDecide()` | Agent 启动前 | userMessage → Embedding → Qdrant 搜索 → 策略（fast/hybrid/slow）|
| `recordAfterAgent()` | Agent 完成后 | 录制工具链 → MySQL + 索引到 Qdrant（新建 collection `behavior_paths`）|
| `collectFeedback()` | 下条消息到来 | 解析反馈信号 → 更新 Beta 分布（α/β）|

**FeedbackParser**：正则词库，区分强正面/温和正面/强负面/温和负面/中性。

**ConfidenceUpdater**：Beta 分布模型，α 成功 +1，β 失败 +1，conf = α/(α+β)。

**PathEmbeddingService**：封装 `EmbeddingService` 生成向量，通过 Qdrant REST API 索引/搜索行为路径。独立 collection `behavior_paths`（Cosine 距离，1024 维），自动创建。

**集成点**（纯增量，不改现有逻辑）：
- `AgentGraphRunner.run()` — 开头调 retrieveAndDecide，结尾调 recordAfterAgent
- `WechatChatBridge.doThink()` — 开头调 collectFeedback

**新增表**：`behavior_paths` / `decision_traces` / `path_evaluations`（3 张 MySQL 表）。

### Phase 2 — Critic 反思（下午）

**CriticEvaluator**：调 DeepSeek 分析失败（三元组：事件 + Agent 动作 + 用户反应），返回结构化 `CriticVerdict`（score/verdict/root_cause/learned_rule）。

**CriticTriggerDecider**：failure/harmful/ignored/partial → 必触发；success+新路径 → 触发一次（总结成功模式）。

**规则注入机制**：
- 规则绑定到路径的 `critic_rules` JSON 列（RAG 命中该路径时才注入，不是全局注入）
- `@JsonProperty` 映射 LLM 输出的 snake_case → Java camelCase

**时间衰减因子**：7 天内 1.0 / 30 天 0.8 / 90 天 0.5 / 超过 0.2。

**MySQL ENUM 恢复**：`decision_traces.outcome` 和 `path_evaluations.user_reaction_type` 从 VARCHAR 改回 ENUM。

### Phase 3 — 路径库维护（傍晚）

**PathMergeService**：`@EventListener(ApplicationReadyEvent)` 启动时全量扫描：
- 按 tool_chain 分组 → 组内两两 cosine sim > 0.85 → 合并 α/β
- 保留最早路径，删除被合并方（MySQL + Qdrant）

**PathMaintenanceScheduler**：
- 每天凌晨 3 点：归档过期路径（90 天未用 + use_count < 10）
- 每天凌晨 4 点：检测矛盾路径（fail≥3 且 success≥3 → 标记 degraded）

**个人权重**：用户使用同一路径 3 次以上，finalConf = 0.7×全局 + 0.3×个人

**热路径保护**：degraded 路径强制走温路径，不参与热路径。

## 调试记录

### 1. 冷启动 trace 为 null 导致 recordAfterAgent 跳过

`PathDecision.coldStart()` 返回 trace=null → `recordAfterAgent()` 第一行 `if (trace == null) return` → 路径从未写入。

**修复**：无论 Qdrant 是否命中，都先创建 trace。0 命中时带 trace 返回 coldStart，确保 recordAfterAgent 能录制。

### 2. Qdrant point ID 格式错误（HTTP 400）

用 `pathId`（如 `path_b158235f-d1e`）作为 Qdrant point ID，Qdrant 只接受 UUID 或 uint64。

**修复**：改用 `UUID.randomUUID().toString()` 作为 point ID，pathId 只存在 payload 中。

### 3. MySQL outcome 列 Data truncated

代码写的值（`"awaiting_feedback"`, `"pending"` 等）超出 ENUM 范围。

**修复**：统一使用 ENUM 内的值（success/partial/failure/ignored/harmful），中间状态用 partial 代替。Phase 3 加 `degraded`。

### 4. SLF4J `{:.2f}` 格式不支持

Python 格式串 `{:.2f}` 在 SLF4J 中不会格式化，直接输出原文本。

**修复**：改用 `String.format("%.2f", value)` 预处理再传入 `{}`。

### 5. Critic JSON snake_case 映射失败

LLM 返回 `what_went_right` 但 Java 字段是 `whatWentRight`（camelCase），Jackson 反序列化失败。

**修复**：`CriticVerdict` 所有字段加 `@JsonProperty` 映射，类加 `@JsonIgnoreProperties(ignoreUnknown = true)`。

### 6. FeedbackParser 反馈信号类型与 MySQL ENUM 不匹配

代码写入 `signal.getType().name().toLowerCase()` 产生 `explicit_positive` 等值，但 `path_evaluations.user_reaction_type` ENUM 原始定义为 `explicit_praise` 等不同值。

**修复**：`path_evaluations.user_reaction_type` ENUM 改为与 `FeedbackSignal.Type` 对齐的值（explicit_positive/explicit_negative/implicit_positive/implicit_negative/neutral/none/other）。

### 7. RAG 召回路径数过多（sim=0.65 就命中）

"骰子"和"天气"之间的 sim 约 0.65，"帮大忙了"和"好的"触发正面反馈后 Critic 也触发了 — 因为 `CriticTriggerDecider` 对 success+newPathCreated 也触发（设计如此）。

### 8. 消息数 54 条导致中央 LLM 跳过 Agent 工具调用

消息历史太长时，DeepSeek 可能直接基于已有知识回复而不调用 Agent，导致该轮无工具链 → 不创建路径。非系统 bug，建议定期清会话。

## 测试验证

- "掷一个六面骰子" → 冷启动创建路径

### Rust 环境搭建

安装 Rust 1.97.1 到 D 盘，设置清华镜像加速，配置 C++ 编译工具链。遇到的问题：
- 默认安装到 C 盘 → 设 RUSTUP_HOME/CARGO_HOME 环境变量改到 D 盘
- 下载限速 6 KiB/s → 换清华镜像
- 文件被占用无法移动 → 重新下载 rustup-init.exe 直接装 D 盘
- C 盘清理 Temp 15G + .m2 1.8G + npm 1.1G

### Tauri 打包踩坑

1. **bundle identifier** — 默认 `com.tauri.dev` 不允许，改为 `com.wechatai.desktop`
2. **crates.io 被墙** — 设置 Cargo 镜像（USTC/SJTU 均超时，最终挂代理直接连 crates.io）
3. **WiX 下载超时** — 打包目标从 `all` 改为 `nsis`，跳过 MSI
4. **Vite 监听 src-tauri/ 崩溃** — `vite.config.js` 加 `watch.ignored: ['**/src-tauri/**']`
5. **打包后通信失败** — `api.js` 区分开发/打包环境：开发走 Vite 代理，打包走 `localhost:8081` 直连

## 晚间主线：桌面端产品化（白底 UI / 多模态 / WRITE 确认 / 提醒渠道分离）

### 1. UI

- ChatGPT 浅色风格：白底主区 + 浅灰侧栏；消息**无气泡**，用户右对齐 / 助手左对齐

- 加载态三点跳动动画；图片/文档合并为一个 📎 上传入口

### 2. REST 多模态（对齐微信能力，不走 iLink）

| 接口 | 作用 |
|------|------|
| `POST /api/v1/chat/image` | multipart 上传 → Qwen-VL 识别 → 拼入用户消息 → 跑图；图片落盘 `upload/chat-images/` |
| `POST /api/v1/chat/file` | multipart → `DocumentService.upload` 同步解析 → 跑图 |
| `GET /api/v1/chat/media/{fileName}` | 历史还原图片 |

历史消息返回 `mediaUrl` / `fileName` / `displayText`，切换会话后仍可显示附件卡片（需本轮起新发的图才有落盘）。

### 3. WRITE 确认（文字回复，无按钮）

桌面 `/chat/send` 检测子 Agent `needsConfirm` → `finishReason=NEED_CONFIRM`，文案为确认提示。  
用户回复「确认/取消」→ `ChatController` 调 `AgentGraphRunner.confirmResume`，不新开一轮编排。  
输入框下方 hint：`请回复「确认」或「取消」`。

### 4. 提醒渠道分离（桌面不依赖 iLink）

**问题**：`RemindScheduler` 到期一律 `WechatChatBridge.think` → `sendText`，`desktop-user` 无 context token 失败。

**方案**（显式 `channel`，不硬编码 userId 判断）：

- DDL：`remind.channel` / `remind.session_id`；新表 `desktop_notification`
- 图状态注入 `KEY_CHANNEL`：`ChatController`→`DESKTOP`，`WechatChatBridge`→`WECHAT`
- `ToolExecuteNode` 注入 `channel`+`sessionId` 给 `setRemind`
- 调度分叉：`WECHAT` 仍走 Bridge；`DESKTOP` → `DesktopRemindDelivery`（会话消息落库 + 通知表）
- 桌面轮询 `GET /api/v1/desktop/notifications`

**踩坑**：`SessionPrepareNode` 曾用 `getOrCreateActiveSession` 覆盖桌面 sessionId，提醒写到错误会话。  
**修复**：`channel=DESKTOP` 且已有 sessionId 时保留请求 sessionId；微信路径不变。

### 5. 需手动执行的 SQL

见仓库 `wechat-ai-session/src/main/resources/db/migration/V3__remind_channel.sql`（项目未启用自动 Flyway）。

### 6. 验证要点

- 桌面：设 1 分钟提醒 → 日志 `setRemind` 的 sessionId = 当前桌面会话 → 到期出现 `🔔 提醒：…`，无 `missing latest context token`
- 微信：提醒仍走 Bridge + iLink（`channel` 默认/显式 WECHAT）
