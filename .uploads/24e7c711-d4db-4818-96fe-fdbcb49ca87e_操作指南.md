## 1. 环境准备

确保已安装以下工具：

| 工具 | 版本要求 | 验证命令 |
|------|---------|---------|
| JDK | **21**（不是 17、不是 11） | `java -version` |
| Maven | 3.9.x | `mvn -version` |
| Git | 任意 | `git --version` |

> ⚠ **JDK 必须为 21**，项目使用了 JDK 21 的语法特性，低版本无法编译。
>
> ⚠ Maven 的 `JAVA_HOME` 必须指向 JDK 21。

## 3. 首次构建

```bash
# 编译所有模块并安装到本地 Maven 仓库（约 30 秒）
mvn install -DskipTests -q
```

看到 `BUILD SUCCESS` 即表示构建成功。

**如果编译报错：**

| 错误 | 原因 | 解决 |
|------|------|------|
| `java: 无效的源发行版 21` | IDE 编译级别没设 JDK 21 | 检查 IDE 中的 Project SDK 设置 |
| `找不到符号` | 依赖模块没装到本地 | 执行 `mvn install -DskipTests` |
| `Could not find artifact` | Maven 仓库里缺少模块 | 执行 `mvn install -DskipTests` |

## 4. 分支规范

### 4.1 分支结构

```
main              ← 主分支（保护），所有成员确认无误后由组长合入
└── dev           ← 开发主分支（保护），组员在此分支上开发、合并
    ├── feat/session  ← 会话模块（组员A）
    ├── feat/document ← 文档模块（组员B）
    ├── feat/wechat   ← 微信接入（组员C）
    └── feat/tools    ← 工具实现（可选）
```

**流程要点：**
- **`main`** 只由组长操作，组员不需要也不应该直接操作 `main`
- **`dev`** 是开发总干线，组员的功能分支从 `dev` 拉，完成后通过 MR 合入 `dev`
- 组长验证所有功能无误后，将 `dev` 合入 `main`

### 4.2 建分支

从最新的 dev 拉自己的开发分支（**不要直接从 main 拉**）：

```bash
# 先确保 dev 是最新的
git checkout dev
git pull

# 创建自己的功能分支（分支名统一用 feat/xxx）
git checkout -b feat/session
# 或
git checkout -b feat/document
# 或
git checkout -b feat/wechat

# 推送到远程
git push -u origin feat/session
```

### 4.3 分支命名规则

| 前缀 | 用途 |
|------|------|
| `feat/` | 新功能（feat/session, feat/document, feat/wechat, feat/tools） |
| `fix/` | 修复 Bug（fix/login-error） |

## 5. 开发流程

### 5.1 你只改自己的模块

每个组员只修改自己负责的模块目录：

| 组员 | 目录 | 对应文档章节 |
|------|------|-------------|
| 你（AI 引擎） | `wechat-ai-ai/` | 第 5 章 |
| 你（工具系统） | `wechat-ai-tool/` | 第 6 章 |
| 组员 A（会话） | `wechat-ai-session/` | 第 3 章 |
| 组员 B（文档） | `wechat-ai-document/` | 第 4 章 |
| 组员 C（微信） | `wechat-ai-wechat/` | 第 7 章 |

**不要修改其他模块的代码。** 如果发现需要改其他模块的接口，在群里通知该模块负责人。

### 5.2 接口契约

- 所有接口定义（interface）已放在对应模块里
- 你只负责**实现**这些接口，**不要改接口签名**
- 接口返回格式必须符合文档的**统一响应规范**（`Result<T>` 结构）
- 新增工具 = 在 `wechat-ai-tool/.../impl/` 下新建 `XxxTool.java`，参考 `QueryWeatherTool.java`

### 5.3 如何验证自己的代码

```bash
# 只编译你改的模块（快速）
mvn compile -pl wechat-ai-session -am

# 如果整个项目都能编译通过
mvn install -DskipTests
```

### 5.4 每次提交

```bash
# 查看改了哪些文件
git status

# 添加要提交的文件（只加自己模块的文件）
git add wechat-ai-session/src/...

# 提交（Commit Message 格式见下方）
git commit -m "feat: 实现会话模块 getOrCreateActiveSession"

# 推送到远程
git push
```

### 5.5 Commit Message 规范

```
格式: <type>: <简短说明>

类型:
  feat:   新功能
  fix:    修复 Bug
  docs:   文档修改
  refactor: 重构
  test:   测试

示例:
  feat: 实现会话 CRUD 接口
  fix: 修复会话过期判断错误
  docs: 更新接口注释
```

## 6. 提交 Merge Request

当你的模块功能开发完成并自测通过后，发起合并请求将代码合入 `dev`。

### 6.1 提 MR 前检查

- [ ] 代码能编译通过：`mvn install -DskipTests`
- [ ] 只包含自己模块的改动
- [ ] 没有 debug 代码（System.out、未使用的变量等）
- [ ] 接口签名与文档一致

### 6.2 在 GitLab 上提 MR

1. 浏览器进入 GitLab 项目：`https://codeserver.youkeda.com/qwqqwqqwq/306-project`
2. 左侧菜单 → **Merge Requests** → **New Merge Request**
3. **Source branch**: 选你的分支（如 `feat/session`）
4. **Target branch**: 选 **`dev`**（不是 `main`）
5. **Title**: 写清楚改动内容，如 `feat: 实现会话模块 getOrCreateActiveSession`
6. **Description**: 简要描述改了哪些文件、实现了什么功能
7. **Assignee**: 指派人选择你
8. 点击 **Create Merge Request**

### 6.3 MR 之后

- 等待审核（组长 review 代码）
- 如果有修改意见，在你的分支上修改后重新 push，MR 会自动更新
- 审核通过后，组长会合入 `dev` 分支
- 所有功能完成且验证无误后，组长统一将 `dev` 合入 `main`

## 7. 同步主分支

当别人合入 dev 后，你需要把最新的 dev 同步到自己的开发分支：

```bash
# 在自己分支上
git checkout feat/document

# 拉取最新的 dev
git fetch origin

# 把 dev 的更新合并到你当前分支
git merge origin/dev

# 如果有冲突，解决后
git add .
git merge --continue

# 推送到远程
git push
```

建议**每天开始开发前先同步一次**，减少后期冲突。

## 8. 常见问题

### Q: 启动项目

```bash
cd wechat-ai-starter
mvn spring-boot:run
```

项目启动后控制台会打印一个二维码链接，**手机微信扫码登录**后才能收发消息。

### Q: 启动报 8080 端口被占用

```bash
# 在任务管理器中找到占用 8080 的进程并结束它
netstat -ano | findstr :8080
# 根据 PID 杀掉进程
taskkill /PID <PID> /F
```

### Q: 编译报循环依赖

```
The dependencies of some of the beans in the application context form a cycle
```

这是已知的设计问题。`application.properties` 里已配置 `spring.main.allow-circular-references=true`，不影响运行。

### Q: 需要新建表

建表 SQL 在接口文档的**附录 E（数据库表结构）**中，执行对应 SQL 即可。目前需要的表：

| 表名 | 所属模块 | 负责人 |
|------|---------|--------|
| `session` | 会话模块 | 组员 A |
| `document` | 文档模块 | 组员 B |
| `message` | AI 模块 | 暂不需要 |
| `async_task` | 任务模块 | 组员 C |

### Q: 本地没有 MySQL / Redis

不影响 AI 引擎 + 微信链路的开发。目前简化图跳过了数据库相关节点，纯聊天场景不依赖 MySQL 和 Redis。如果启动报数据源错误，可以先注释掉 `application.properties` 里的数据库配置，或者本地安装 MySQL 8.0 + Redis 7.x。

### Q: Maven 依赖下载慢

配阿里云镜像（`~/.m2/settings.xml`）：

```xml
<mirrors>
    <mirror>
        <id>aliyun</id>
        <mirrorOf>central</mirrorOf>
        <name>Aliyun Maven Mirror</name>
        <url>https://maven.aliyun.com/repository/public</url>
    </mirror>
</mirrors>
```
