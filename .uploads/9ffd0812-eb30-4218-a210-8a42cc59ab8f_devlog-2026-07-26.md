## 二、Step 3-4：AgentInvoker + Agent 注册

### AgentInvoker

自包含小 ReAct 循环：调 LLM（只传工具白名单）→ 执行工具（支持本地/MCP）→ 回填结果 → 继续循环。

### Agent 工具注册

`AgentToolRegistration` 在 `@PostConstruct` 中将 `generalAgent` 和 `taxiAgent` 注册为外部工具（source=`AGENT:General` / `AGENT:Taxi`），中央 LLM 看到 2 个专家工具。

### 涉及文件

| 文件 | 操作 | 说明 |
|------|:--:|------|
| `AgentResult.java` | 新 | 子 Agent 返回体 |
| `AgentInvoker.java` | 新 | 手动 while 循环 + 反射执行工具 |
| `AgentToolRegistration.java` | 新 | 注册 Agent 工具到 ToolRegistry |
| `ToolExecuteNode.java` | 改 | +Agent 路由分支（source.startsWith("AGENT:")） |
| `ChatGraphConfig.java` | 改 | ToolExecuteNode 构造传 AgentInvoker |

### Agent 路由流程

```
ToolExecuteNode.apply()
  ├─ getSource(toolName) → "AGENT:General"/"AGENT:Taxi"
  ├─ AgentInvoker.invoke(agentId, task, agentTools, 5, 30s)
  ├─ 返回 summary → 作为 tool result 回填中央状态
  └─ 中央 LLM 看到 summary → 组织最终回复
```

## 三、Step 5：wechat-ai-agent 独立模块

### 动机

Agent 框架从 ai/tool 模块中抽出，避免循环依赖。核心设计：`LlmCaller` 接口由 ai 模块实现，agent 模块不依赖 ai。

### 模块结构

```
wechat-ai-agent/
├── pom.xml                          （依赖 tool + common，不依赖 ai）
└── com/wechatai/agent/
    ├── LlmCaller.java               ← 接口：callLlm(messages, tools)
    ├── AgentResult.java             ← 子 Agent 返回体
    ├── AgentInvoker.java            ← 子 Agent 小 ReAct
    └── AgentToolRegistration.java   ← 注册 Agent 工具
```

### 依赖链

```
starter → wechat → ai → agent → tool → common
                        （单向，无循环）
```

### 涉及文件

| 文件 | 操作 | 说明 |
|------|:--:|------|
| `wechat-ai-agent/pom.xml` | 新 | 新模块 POM |
| `LlmCaller.java` | 新 | LLM 调用契约接口 |
| `AgentResult.java` | 移 | ai/agent → agent |
| `AgentInvoker.java` | 移 | ai/agent → agent（LlmService → LlmCaller） |
| `AgentToolRegistration.java` | 移 | tool/registry → agent |
| 根 `pom.xml` | 改 | +module + dependencyManagement |
| `wechat-ai-ai/pom.xml` | 改 | +agent 依赖 |
| `wechat-ai-starter/pom.xml` | 改 | +agent 依赖 |
| `LlmService.java` | 改 | implements LlmCaller |

### 循环依赖处理

多个注入点需要 `@Lazy`：
- `AgentToolRegistration` → `@Lazy ToolRegistry`
- `AgentInvoker` → `@Lazy ToolRegistry`
- `AgentToolRegistry` → `@Lazy ToolRegistry`

## 四、Step 6：LLM 自主意图识别

### 改前

```java
// 关键词匹配
if (matchesAny(msg, "打车", "导航", "路线"...)) {
    return taxiTools;
}
```

### 改后

```java
// Agent 模式：中央 LLM 始终看到 2 个 Agent 工具，自己判断调哪个
List<ToolDefinitionVO> agentTools = agentToolRegistry.getAgentTools();
if (!agentTools.isEmpty()) {
    return agentTools;  // [generalAgent, taxiAgent]
}
```

### 效果

| 消息 | 中央 LLM 行为 |
|------|------|
| 闲聊 | 直接回复（不调工具） |
| "今天天气怎么样" | 选 generalAgent |
| "帮我去天安门" | 选 taxiAgent |
| "从A打车到B" | 选 taxiAgent |

### 关键修复

DeepSeek V4 Pro 在消息历史中有旧 tool_calls 时会"复用"不存在的工具。修复：
1. 清空 MySQL message 表旧数据
2. `callLlm()` 加 `"tool_choice": "auto"` 显式约束
3. 新对话消息数=2，无历史污染

## 五、Step 7：AgentGraphRunner — 子 Agent 走 LangGraph 图

### 动机

`AgentInvoker` 是手动 while 循环，没有 SkillManager、DB 持久化、MemorySaver。改为 `AgentGraphRunner` 自建独立 LangGraph 图，共用同一套节点实现（LlmThinkNode、ToolExecuteNode）。

### 架构

```
AgentGraphRunner（自建图，不依赖 simpleChatGraph bean）
  ├── PrepareInputNode
  ├── SessionPrepareNode（messageHistory 预填充，跳过查库）
  ├── LlmThinkNode（使用 LlmService.callLlm）
  └── ToolExecuteNode（Agent 路由指向 AgentGraphRunner 自身）
  
  编译：CompileConfig.interruptBefore("tool_execute") + MemorySaver
  入口：compiledGraph.invoke(initData, config)
```

### 参数化支持

为让同一套图既服务中央又服务子 Agent，`LlmService.think()` 支持从 state 读取覆盖参数：

| state key | 作用 |
|------|------|
| `KEY_SYSTEM_PROMPT_OVERRIDE` | 子 Agent 自定义 system prompt |
| `KEY_AGENT_TOOLS` | 子 Agent 工具白名单 |

中央不设这两个 key 时，使用默认 SYSTEM_PROMPT 和 `selectToolsByIntent()`。

### 涉及文件

| 文件 | 操作 | 说明 |
|------|:--:|------|
| `AgentGraphRunner.java` | 新 | 自建图 + 编译 + invoke + 中断恢复循环 |
| `ChatGraphState.java` | 改 | +KEY_SYSTEM_PROMPT_OVERRIDE, KEY_AGENT_TOOLS |
| `LlmService.java` | 改 | think() 读 state 自定义 prompt 和工具列表 |
| `ToolExecuteNode.java` | 改 | Agent 路由切到 AgentGraphRunner.run() |
| `ChatGraphConfig.java` | 改 | ToolExecuteNode 构造传 AgentGraphRunner |

### 序列化修复

`ToolDefinitionVO` 加 `implements Serializable` —— MemorySaver 在 addCheckpoint 时用 Java 序列化克隆 state，`agentTools` 是 `List<ToolDefinitionVO>` 必须可序列化。

## 六、Step 8：图中断下沉

### 改前

| 图层 | 中断 |
|------|:--:|
| 中央 compiledChatGraph | interruptBefore("tool_execute") |
| 子 Agent compiledGraph | 无中断 |

### 改后

| 图层 | 中断 | 原因 |
|------|:--:|------|
| 中央 compiledChatGraph | **无中断** | 中央只分发 READ Agent 工具，无需 WRITE 确认 |
| 子 Agent compiledGraph | **interruptBefore("tool_execute")** | 子 Agent 执行 WRITE 工具（taxi_create_order、sendEmail 等） |

### 子 Agent 中断恢复循环

```java
// AgentGraphRunner.run()
result = compiledGraph.invoke(initData, config);
while (result.isPresent() && resumeCount < 50) {
    if (state.toolExecutionRequests == null) {
        return AgentResult.ok(state.getReply());  // 任务完成
    }
    result = compiledGraph.invoke(null, config);  // 自动恢复
    resumeCount++;
}
```

当前所有工具自动恢复（同 AgentInvoker 行为）。WRITE 工具确认后续接入。

## 七、踩坑记录

| # | 问题 | 根因 | 解决 |
|:--:|------|------|------|
| 1 | DeepSeek 在只有 2 个 Agent 工具时调用 queryWeather | 消息历史中有旧 tool_calls，LLM 从上下文"学习" | 清空 DB + tool_choice: "auto" |
| 2 | AgentToolRegistration → ToolRegistry 循环依赖 | 未加 @Lazy | 构造器加 @Lazy |
| 3 | AgentGraphRunner → compiledAgentGraph 循环依赖 | CompiledGraph 是 final class，CGLIB 代理失败 | 改为自建图，不依赖 bean |
| 4 | NotSerializableException: ToolDefinitionVO | MemorySaver 用 Java 序列化克隆 state | implements Serializable |
| 5 | invoke(null, config) 调用歧义 | null 类型推断失败 | 强制转换 (Map<String, Object>) null |
| 6 | AgentToolRegistration 搬到 agent 模块后循环依赖 | 丢失 @Lazy | 补 @Lazy |
| 7 | ChatGraphConfig 中 AgentGraphRunner 参数名不一致 | 先改 import 没改方法签名 | 全部统一 |
