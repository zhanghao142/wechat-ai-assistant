### 7/17（周五）— 核心链路打通 

**主要工作**：从桩代码实现到全链路可运行

#### 1. LLM 引擎（LlmService）
- 放弃 LangChain4j `OpenAiChatModel`（兼容性问题）
- 改用 `RestClient` 直调 DeepSeek API，稳定运行
- 支持标准 OpenAI 兼容格式，tools 参数传递工具清单

#### 2. 工具系统（ToolRegistryImpl）
- 从空实现重写为 `@Tool` 懒扫描注册机制
- 解决 Spring 循环依赖（3 轮迭代：@PostConstruct → @Lazy → 懒扫描）
- 自动推导参数 JSON Schema（String → string、int → integer 等）
- 支持运行时工具启停（toggle）

#### 3. 工具执行（ToolExecuteNode）
- 完整实现反射调用 @Tool 方法
- 支持参数类型自动转换（JSON → String/Integer/List 等）
- 错误结果回填 LLM

#### 4. LangGraph 图编排
- 简化图 `simpleChatGraph`（跳过 session_prepare，不依赖数据库）
- ReAct 循环：llm_think → tool_execute → llm_think → END
- 修复 8 个调试问题（不可修改 Map、消息链缺失、死循环等）

#### 5. 微信 iLink 接入
- iLink SDK 扫码登录，消息轮询接收
- AI 引擎回复通过 `client.sendText()` 推送给用户
- 同步处理（iLink 无 5s 超时限制）

#### 6. 多轮对话记忆
- `ConcurrentHashMap` 按 userId 缓存 messageHistory
- 每次 graph.invoke() 前后传入/取回历史
- 边界：首次对话/进程重启/多用户隔离

#### 7. SYSTEM_PROMPT 提示词
- 24 行 → 70 行，结构化回复格式
- 角色"小微"，回复长度控制 200 字
- 天气/错误两种回复模板

**验证结果**：
```
用户发送"查询一下南京的天气"
→ LLM 识别意图 → 调 queryWeather
→ 回复"南京市：阴，33°C，湿度65%，西南风4级"
→ 微信收到回复 
```

### 7/18（周六）— 多轮对话修复 + 识图优化

**主要工作**：修复消息历史维护的两个 Bug，优化识图提示词

#### Bug 1：assistant 回复未存入 messageHistory
- **根因**：普通回复路径缺少 `messages.add(assistantMsg)`，LLM 看不到自己回答过什么
- **修复**：补一行代码

#### Bug 2：ReAct 循环中 user 消息重复追加
- **根因**：`state.getUserMessage()` 在图生命周期内固定不变，ReAct 循环二次进入时无条件追加
- **修复**：当消息列表最后一条 role 为 `tool` 时跳过追加

#### 识图提示词优化
- 从纯描述改为结构化三块输出：`【文字】`、`【描述】`、`【类型】`
- 文字提取优先级最高，适合截图场景
- SYSTEM_PROMPT 新增图片处理规则

#### wechat 模块精简
- 清理已废弃的公众号 REST 端点及相关空壳代码，共删除 9 个文件
- wechat 模块只保留 `WechatServiceImpl.java`（iLink SDK 登录/收发消息/AI引擎调度）
- 接口文档第 7 章同步更新为 iLink SDK 接入说明

#### 语音识别 — iLink SDK 原生转写
- iLink SDK 2.1.0 → 2.3.3，VoiceItem 新增 getText() 直接返回微信转写文字
- 删除 AsrService 及 DashScope SDK 依赖，零额外 API 调用

#### AI 引擎调用异步化
- 新增按用户隔离的单线程池，callAiEngine 投递到后台执行
- poll 线程永不阻塞，解决消息丢失问题
- 同用户消息保序，不同用户可并行处理

**验证结果**：
```
用户发图（冰红茶+纸巾+耳机盒）
→ Qwen-VL 识别 → LLM 回复图片内容 → 问候
用户"杭州天气咋样" → LLM 查天气 → 回复
用户"适合喝这个不" → LLM 直接推理 → 不再重复查天气 
```

## 四、技术决策汇总

| 决策 | 时间 | 原因 |
|:----|:----:|:-----|
| 放弃 LangChain4j Agent，RestClient 直调 DeepSeek | 7/17 | OpenAiChatModel 兼容性差，框架黑盒不好排错 |
| @Tool 懒扫描注册（3 轮迭代） | 7/17 | 解决 @PostConstruct 导致的 Bean 循环依赖 |
| LangGraph 状态只通过返回值传递 | 7/17 | `state.data()` 返回 UnmodifiableMap，原地修改无效 |
| 允许 Spring 循环引用 | 7/17 | LlmService ↔ ToolRegistry 间接循环，仅在启动时存在 |
| messageHistory 判断 `role == tool` 跳过追加 | 7/18 | ReAct 循环中 userMessage 固定不变，避免重复 |
| 识图提示词结构化三块输出 | 7/18 | 文字优先 + 类型区分，比纯描述更灵活 |
