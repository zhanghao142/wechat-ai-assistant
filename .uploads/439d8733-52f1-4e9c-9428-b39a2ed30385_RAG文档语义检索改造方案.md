# RAG 文档语义检索改造方案

> 2026-07-29 | 方案 C：在 LlmService.think() 中完成 RAG 检索

## 1. 背景与目标

### 当前问题

```
用户消息 → llm_think → LLM 决定调 searchDocument → tool_execute → llm_think（第二轮）
                              ↑                              ↑
                        多一次 LLM 往返              MySQL FULLTEXT 关键字匹配
```

1. **关键字匹配，不是语义匹配**：用户说"退款条款"搜不到标题写的是"退款政策"的段落
2. **多一轮 LLM 往返**：LLM 要先决定"我需要查文档"再调工具，增加延迟和 token 消耗
3. **依赖 LLM 判断**：LLM 可能忘记调用 `searchDocument`，导致明明有文档却没用到

### 改造目标

用户消息到达后，**在 LLM 思考之前**自动从 Qdrant 向量库检索相关文档 chunk，注入 system prompt。

### 为什么选方案 C（LlmService 内嵌 RAG）

不改图拓扑、不动 ChatGraphConfig。`LlmService.think()` 已经在做 system prompt 增强（`skillManager.enrich()`），RAG 检索本质上是同一种操作——往 base prompt 末尾拼接内容。放在一起：

- `ChatGraphConfig` 一行不动，ReAct 循环零风险
- 跟随现有模式，代码改动面最小
- RAG 检索 + Skill 注入 = 同一句话里的两个步骤，顺序任意可调
- 回滚简单：删掉 RAG 那几行就恢复原样

---

## 2. 架构设计

### 图拓扑（不变）

```
START → prepare_input → session_prepare → llm_think ⇄ tool_execute → END
                                              ↑
                                   RAG 检索发生在这里
                                   （LlmService.think() 内部）
```

### 两条数据流

**写路径（文档上传 → 索引）**：

```
DocumentServiceImpl.upload/parse
  → 解析得到 content（已有，不变）
  → ChunkService.split(content) → List<String> chunks
  → EmbeddingService.embedBatch(chunks) → List<List<Float>> vectors
  → QdrantService.indexChunks(fileId, sessionId, userId, chunks, vectors)
```

**读路径（用户消息 → 检索 → 生成）**：

```
LlmService.think(state)
  → userMessage = state.getUserMessage()          // 已有
  → qv = EmbeddingService.embed(userMessage)       // 新增
  → chunks = QdrantService.search(sessionId, qv)   // 新增（filter sessionId）
  → 拼接 chunks + basePrompt → enrichedPrompt       // 新增
  → skillManager.enrich(state, enrichedPrompt)      // 已有
  → 调 DeepSeek API                                  // 已有
```

### 注入格式

检索到 chunks 后在 system prompt 末尾追加：

```
## 相关文档内容
以下是从你上传的文档中检索到的相关内容，优先参考这些内容回答问题：

【来源：xxx.pdf】
...chunk 文本...

【来源：xxx.docx】
...chunk 文本...
```

然后 Skill 的 `getPromptSegment()` 继续拼在后面（如果上一轮有工具调用的话）。

### Step 3: 新增 `ChunkService`（wechat-ai-document）

```
文件：com.wechatai.document.service.ChunkService
```

职责：将文档内容切分为固定大小的文本块。

```
@Component
class ChunkService:
    split(content, maxChars=500, overlapChars=50) → List<String>

切分策略：
  1. 优先在 \n\n（段落边界）处切
  2. 其次在 \n（换行）处切
  3. 最后在 。！？\n 处切
  4. 相邻 chunk 重叠 50 字符，保证跨 chunk 的语义连续
  5. 单 chunk 不超过 maxChars 字符
```

### Step 4: 新增 `EmbeddingService`（wechat-ai-document）

```
文件：com.wechatai.document.service.EmbeddingService
```

职责：调用 DashScope Embedding API，将文本转为向量。复用 Spring `RestClient` + JDK `HttpClient` 模式（与 `LlmService` 一致的 HTTP 客户端风格）。

```
@Service
class EmbeddingService:
    init():
        httpClient = HttpClient.newBuilder().connectTimeout(30s).build()
        restClient = RestClient.builder().requestFactory(httpClient).build()
        配置 readTimeout=60s（embedding 比 chat 快）

    embed(text) → List<Float>
        调 POST {baseUrl}，body={model, input: text}
        返回 response.data[0].embedding

    embedBatch(texts) → List<List<Float>>
        调 POST {baseUrl}，body={model, input: texts}
        返回 response.data[*].embedding

    API 格式（OpenAI 兼容）:
        Authorization: Bearer {apiKey}
        {"model": "text-embedding-v2", "input": "文本内容"}
```

### Step 5: 新增 `QdrantService`（wechat-ai-document）

```
文件：com.wechatai.document.service.QdrantService
```

职责：封装 Qdrant Java SDK，提供索引和检索能力。

```
@Service
class QdrantService:
    init():
        通过云端 URL + API Key 连接 Qdrant
        检查 collection 是否存在 → 不存在则创建
        vector 维度 = 1536，距离度量 = COSINE
        log "✅ QdrantService 初始化完成，collection=document_chunks"

    indexChunks(fileId, sessionId, userId, fileName, chunks, embeddings):
        每个 chunk 构造一个 Point：
          id = UUID
          vector = embedding
          payload = {userId, sessionId, fileId, fileName, text, chunkIndex}
        批量 upsert

    search(sessionId, queryEmbedding, topK=5, minScore=0.5) → List<ChunkResult>:
        Filter: must(sessionId == sessionId)
        返回 topK 条，score >= minScore
        返回 record ChunkResult(fileId, fileName, text, score)

    deleteByFileId(fileId):
        Filter: must(fileId == fileId) → delete all points
```

**隔离机制**：

```
检索时 filter sessionId = 当前会话

  Qdrant 内部：
  ┌────────────────────────────────────────────────┐
  │ Point {id:xxx, vector:[...], payload:{         │
  │   sessionId: "sess_alice", userId: "alice",    │
  │   fileId: "f_001", text: "退款政策..."}         │
  ├────────────────────────────────────────────────┤
  │ Point {id:yyy, vector:[...], payload:{         │
  │   sessionId: "sess_bob",   userId: "bob",      │ ← 同 collection
  │   fileId: "f_002", text: "年终奖..."}           │    不同 session
  └────────────────────────────────────────────────┘

  查 alice → filter sessionId="sess_alice" → 只命中上一条
```

### Step 6: 改造 `DocumentServiceImpl`（wechat-ai-document）

**修改文件**：`DocumentServiceImpl.java`

新增依赖注入：`ChunkService`, `EmbeddingService`, `QdrantService`

三处改动：

```
① upload() — 解析成功后追加：
    if (content != null && !content.isEmpty()) {
        chunks = chunkService.split(content)
        embeddings = embeddingService.embedBatch(chunks)
        qdrantService.indexChunks(fileId, sessionId, userId, fileName, chunks, embeddings)

    同上 indexChunks 逻辑（先 deleteByFileId 再 indexChunks）

③ delete() — 追加：
```

三处删除（旧检索链路）：

```

⑤ 删除 extractSnippet() 私有方法
⑥ 删除 SNIPPET_MAX_LEN 常量
```

### Step 7: 改造 `LlmService.think()`（wechat-ai-ai）

**修改文件**：`LlmService.java`

新增依赖注入：`EmbeddingService`, `QdrantService`

在 `think()` 方法中，`skillManager.enrich()` 之前插入 RAG 检索：

```java
public Map<String, Object> think(ChatGraphState state) {
    // ... 现有代码：构建消息列表、获取 basePrompt ...

    // ====== 新增：RAG 检索（方案 C） ======
    String sessionId = state.getSessionId();
    String userMessage = state.getUserMessage();
    if (userMessage != null && !userMessage.isBlank()) {
        try {
            List<Float> queryEmbedding = embeddingService.embed(userMessage);
            List<QdrantService.ChunkResult> chunks =
                qdrantService.search(sessionId, queryEmbedding,
                    ragTopK, ragMinScore);
            if (!chunks.isEmpty()) {
                StringBuilder ragBlock = new StringBuilder("\n\n## 相关文档内容\n");
                ragBlock.append("以下是从你上传的文档中检索到的相关内容，优先参考这些内容回答问题：\n\n");
                for (var c : chunks) {
                    ragBlock.append("【来源：").append(c.fileName()).append("】\n");
                    ragBlock.append(c.text()).append("\n\n");
                }
                basePrompt = basePrompt + ragBlock.toString();
                log.info("【RAG】检索到 {} 个 chunks → 注入 system prompt", chunks.size());
            }
        } catch (Exception e) {
            log.warn("【RAG】检索失败，降级为无文档模式: {}", e.getMessage());
            // RAG 失败不影响主流程，继续用 basePrompt
        }
    }
    // ====== RAG 结束 ======

    // 已有：Skills 注入
    String enrichedPrompt = skillManager.enrich(state, basePrompt);
    // ... 后续不变 ...
}
```

**关键点**：
- RAG 检索在 `skillManager.enrich()` **之前**，这样 Skills 规则可以覆盖 RAG 注入的内容
- RAG 失败 catch 异常，降级回原流程，不影响正常对话
- 用 `userMessage`（用户原文）而非对话历史做 embedding，避免噪声
- `basePrompt` 是 `static final` 字符串，每次 think() 从原始值拼接，不会重复累加

| 1 | 编译通过 | `./mvnw compile` | 无报错 |
