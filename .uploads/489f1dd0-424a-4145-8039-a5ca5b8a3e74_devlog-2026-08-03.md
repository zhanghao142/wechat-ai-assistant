## 概述

今天打通桌面 **邮箱验证码登录**，并让桌面会话真正写入 `session` 表、可挂到正式 `userId`。未登录仍用占位 `desktop-user`，满 3 轮用户消息后强制登录。

**关键约定**：

| 概念 | 约定 |
|------|------|
| userId | 正式用户 = `app_user.user_id`（UUID）；未登录 = `desktop-user`；微信 = openid |
| sessionId | 桌面仍由前端生成 UUID；后端 **ensure 写入**，不覆盖为微信式 getOrCreate |
| 展示名 | 「用户」+ 8 位数字，由 userId 哈希派生，不落库 |

## 二、今日开发内容

### 2.1 邮箱验证码

- QQ SMTP 发 6 位码；内存 TTL 5min；同邮箱频控 60s。  
- 校验成功 → `findOrCreateByEmail` → 返回 `{ userId, email }`。  
- 前端写入 `localStorage.userId`；`getUserId()` 每次读本地。

### 2.2 UI

- 登录浮层：邮箱下一步 → 六位 OTP。  
- 登录后隐藏右上角「登录」；侧栏左下展示名，可退出。  
- `handleSend`：未登录且本会话 user 消息 ≥ 3 → 弹登录、保留输入；登录后自动发送。

### 2.3 Session 落库

此前桌面跳过 `getOrCreateActiveSession`，只写 `message`，库中看不到会话。  
现：`ensureDesktopSession(userId, sessionId)` 在 Prepare 阶段写入/续期，`source=API`。

### 5.1 展示名不落库
