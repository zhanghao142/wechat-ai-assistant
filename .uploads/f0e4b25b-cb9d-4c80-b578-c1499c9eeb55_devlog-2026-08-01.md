## 概述

今天把桌面回复从「整包 JSON 一次刷出」改成 **编排算完后 SSE 分片推送**，前端呈现打字机效果。业务编排、工具、确认续跑逻辑不变；**不是** LLM token 真流式。

**关键决定**：只改出站形态（JSON → SSE 分片），不改 `runChat` / 图结构；桌面落库由 `ChatController` 统一负责，避免与 `LlmService` 双写。

## 二、今日开发内容

### 2.1 后端 SSE 接口

路径与 JSON 版一一对应，请求体相同，响应 `text/event-stream`：

| 路径 | 对应 JSON |
|------|-----------|
| `POST /api/v1/chat/send-stream` | `/send` |
| `POST /api/v1/chat/image-stream` | `/image` |
| `POST /api/v1/chat/file-stream` | `/file` |

事件顺序：`meta` → 若干 `delta` → `done`（或 `error`）。  
分片常量：`STREAM_CHUNK_CHARS=2`，`STREAM_CHUNK_DELAY_MS=28`。

### 2.2 前端消费

- `fetch` + `ReadableStream` 解析 SSE。  
- loading 三点；收到 `delta` 后固定气泡 id 追加。  
- 切会话 `AbortController` 取消旧流。

### 2.3 去重（历史「两遍」）

1. **双落库**：DESKTOP 下 `LlmService` 不再写 message，由 Controller 写。  
2. **前端竞态**：流式中禁止过期 `getHistory` 回写去掉 `streaming` 标记。
