# 地图相机飞线演示方案（暂定）

> **状态**: 暂定方案，尚未开工  
> **日期**: 2026-08-04  
> **目标**: 用「上帝视角沿路径飞 + 到点停靠出卡片」强化复杂 Agent 场景的视觉冲击  
> **范围**: 桌面端演示优先；不纳入微信 iLink 出站  
> **非目标（本期不做）**: 真第一人称街景漫游、完整 3D 建模引擎、跟每个 token 抖动镜头  

相关现行能力见：`desktop-app-solution.md`、`devlog/devlog-2026-08-04.md`（SSE `progress`、并行 Agent、`taxiAgent` 出行工具）。

---

## 1. 背景与动机

桌面端已具备：

- 多步工具链（搜 / 读 / 出行规划 / 提醒等）
- SSE 过程进度（淡灰文案）
- 并行 Agent、研究报告落盘等

复杂场景在**能力上**已经能讲清楚，但观众仍主要盯聊天气泡，**空间感与「正在推进」的体感偏弱**。

本方案用一张倾斜 3D 地图 + 相机沿规划路径飞行，把 Agent 产出的**航点 / 停靠信息**钉在地理上，形成「复杂推理 + 强视觉」的演示组合。

---

## 2. 效果描述（做成什么样）

### 2.1 整体观感

不是游戏漫游，更像**航拍跟拍导航演示片**：

1. **开场（2～3s）**  
   高空上帝视角看清城市与整条高亮路线 → 镜头俯冲、略侧倾，落到起点上空。

2. **飞行中**  
   半空俯视沿路平滑前进；聊天区可同时出字或展示进度；镜头按**航点**推进，不跟每个字抖。

3. **到站停靠（每站 2～4s）**  
   镜头刹住或轻微绕点；弹出半透明信息卡片（标题 + 2～3 行要点）；再起飞去下一站。

4. **收尾**  
   终点后再拉高回上帝视角，整条路径完整点亮；可与正式回复 / 附件简报衔接。

### 2.2 桌面布局（建议）

```
┌──────────────┬─────────────────────────────┐
│  侧栏会话     │  地图飞线区（主视觉）          │
│              │  · 3D 倾斜地图               │
│              ├─────────────────────────────┤
│              │  对话 / 进度文案（辅）         │
└──────────────┴─────────────────────────────┘
```

演示模式可一键「地图全屏 / 分栏」；日常聊天默认关闭地图层，仅在命中出行/多航点任务时打开。

## 3. 方案选型

| 方案 | 说明 | 本期 |
|------|------|:----:|
| A. 地图 SDK 相机飞线 | Mapbox / 高德 JS API 等，画线 + `flyTo` / 沿路径插值 | ✅ **采用** |
| B. Cesium / Three 全 3D | 上天入地更炸，数据与性能成本高 | ❌ 二期再评 |
| C. 预渲染视频对轴 | 最稳，但非实时 | ⚠ 路演备胎 |

**推荐 A**：与现有 `taxiAgent`（路线/地点）数据模型接近，几天～两周可做出可演示版本。

地图供应商待选型（需密钥与商业授权）：

- 优先考虑国内路网与中文标注（高德 / 百度）
- 若演示可接受海外底图，Mapbox 镜头 API 成熟、文档友好

## 4. 与现有架构的衔接

### 4.1 原则

- **Agent 负责算**：途经点、停靠文案、顺序  
- **前端负责演**：相机剧本、卡片、时间轴  
- **事件驱动，不 token 驱动**：工具步骤或航点就绪后再推进一步动画  

### 4.2 建议数据协议（航点清单）

Agent（或后端整理）输出结构化轨迹，例如：

```json
{
  "sceneId": "nav-demo-001",
  "title": "国贸 → 首都机场 T3",
  "path": [
    { "lng": 116.461, "lat": 39.908, "name": "起点·国贸", "dwellMs": 2500,
      "card": { "title": "出发", "lines": ["建议预留安检时间", "当前路况：缓行"] } },
    { "lng": 116.512, "lat": 39.925, "name": "东三环", "dwellMs": 3000,
      "card": { "title": "途经", "lines": ["预计剩余 28 分钟"] } },
    { "lng": 116.598, "lat": 40.080, "name": "终点·T3", "dwellMs": 4000,
      "card": { "title": "到达", "lines": ["航站楼：T3", "天气：晴 26°C"] } }
  ],
  "polyline": [[116.461, 39.908], [116.512, 39.925], [116.598, 40.080]]
}
```

字段可精简；`polyline` 也可由地图服务根据起终点请求得到，Agent 只给停靠点。

### 4.3 传输方式（与 SSE 对齐）

在现有 `progress` / `delta` / `done` 之外，增加可选事件（名称暂定）：

| event | 含义 |
|-------|------|
| `nav` 或 `flight` | 下发完整 `FlightPlan`（一次给齐，前端自播） |
| `nav-step`（可选） | 按步下发：到达第 i 站时再推，便于和工具进度对齐 |

**一期建议**：工具链跑完（或路线工具返回后）**一次下发完整 FlightPlan**，前端按时间轴自播；实现简单、演示可控。

**二期**：边规划边推 `nav-step`，与 `progress`（正在查路 / 正在估时）同步。

### 4.4 后端职责（增量）

| 项 | 说明 |
|----|------|
| `taxiAgent` / 路线类工具 | 已有起终点、路径时，增加「规范化为 FlightPlan」的装配逻辑 |
| 或专用整理节点 | 中央/子 Agent 结果里解析坐标与文案 → `FlightPlan` |
| ChatController SSE | `emitter.send(event.name("flight").data(plan))` |
| Skill（可选） | `FlightDemoSkill`：约定何时产出航点、卡片文案规范 |

微信通道可不接；仅 `channel=DESKTOP` 推送。

### 4.5 前端职责（desktop/）

| 项 | 说明 |
|----|------|
| 地图容器组件 | 如 `FlightMap.jsx`，封装 SDK 初始化 / 销毁 |
| 播放器 | 根据 FlightPlan：俯冲 → 沿点飞行 → 停靠卡片 → 拉高 |
| SSE | `consumeSse` 增加 `onFlight` |
| UI | 演示开关、跳过动画、重播 |

密钥放环境变量 / 本地配置，**不进仓库明文**。

## 5. 镜头剧本（默认参数，可调）

| 阶段 | 行为 | 建议时长 |
|------|------|----------|
| intro | 上帝视角 fit 整条路线 | 1.5～2s |
| dive | 俯冲到 path[0] 上空 | 1.5～2s |
| leg i→i+1 | 沿折线插值飞行，保持倾斜角 | 按距离 3～8s |
| dwell i | 停靠 + 显示 card | path[i].dwellMs 或 2～4s |
| outro | 拉高 + fitBounds 全路径 | 2s |

交互：

- 支持「跳过飞线，直接看结果」  
- 支持重播  
- 用户切会话 / 新消息：中止当前播放

## 6. 演示场景（建议主用例）

与复杂 Agent 叙事绑定，避免「为飞而飞」：

**主场景：出行多停靠决策**

> 弱指向示例：帮我规划从国贸到首都机场，路上标出 2～3 个关键节点（路况/建议），最后用一段话总结；能在地图上走一遍最好。

期望链路：

1. `taxiAgent`（或 general + 地图工具）出路线与节点  
2. 后端组装 `FlightPlan` → SSE `flight`  
3. 前端飞线 + 停靠卡片  
4. 聊天区给出文字总结（可 MD 渲染）  

**加菜（并行）**：同轮再查天气 / 设提醒 —— 卡片文案可带天气与提醒时间，体现并行能力，但**飞线只跟地理路径走**，避免镜头剧本过乱。

不推荐一期用「政策深研简报」当飞线主场景（无天然连续路径）；深研仍用现有搜读写文档演示。

## 7. 分期计划

### Phase 0 — 协议与假数据（0.5～1 天）

- 定稿 `FlightPlan` JSON  
- 前端用写死的北京样例航点跑通镜头（无后端）  

### Phase 1 — 可演示 MVP（约 3～7 天）

- 接入地图 SDK + 播放器  
- SSE 一次下发 plan（可用后端 mock 或手工接口）  
- 分栏 UI + 跳过 / 重播  

### Phase 2 — 接真 Agent（约 3～5 天）

- 路线工具结果 → FlightPlan  
- 与 `progress` 文案协同  
- 演示开关与失败降级（无坐标则只聊文字）  

### Phase 3 — 增强（可选）

- 边规划边 `nav-step`  
- 更细路网 polyline  
- 录屏备胎轨

## 9. 成功标准（演示验收）

1. 给定样例 `FlightPlan`，桌面端完整播放：俯冲 → ≥2 次停靠卡片 → 拉高。  
2. 从一次真实（或半真实）出行任务到飞线播放，人工干预 ≤1 步。  
3. 失败时不白屏：无 plan 则静默回纯聊天。  
4. 路演 1 分钟内观众能理解「Agent 规划了路径并按站说明」。

## 10. 明确不做（本期）

- 真第一人称沿街行走 / 街景序列帧

- 微信内嵌同一套 3D  
- 镜头与 LLM 每个 token 强绑定
