### 里程碑 2：ToolRegistryImpl 工具扫描（上午）

**涉及文件**: `ToolRegistryImpl.java`

**设计变更**：

| 版本 | 方案 | 问题 |
|------|------|------|
| v1（@PostConstruct） | `init()` 中扫描 `ApplicationContext` | 与 `ToolController` 形成循环依赖 |
| v2（@Lazy 类级） | 类上加 `@Lazy` | 不够，构造器参数仍触发 |
| v3（懒扫描） | 第一次被调用时才扫描，`synchronized` 保证一次 | ✅ 解决 |

**最终方案**：

```java
private volatile boolean scanned = false;

private void ensureScanned() {
    if (!scanned) {
        synchronized (this) {
            if (!scanned) {
                scanToolBeans();
                scanned = true;
            }
        }
    }
}
```

**编译器参数问题**：Java 编译时参数名会被抹成 `arg0`、`arg1`，但当前 `@P("城市名称")` 的描述已够用，LLM 不需要参数名也能正确传参。

**文档对应**: 接口文档 6.4 节

### 里程碑 3：LLM 引擎 — RestClient 直调 DeepSeek（上午）

**涉及文件**: `LlmService.java`（新增 `application.properties` 配置）

**方案选型对比**：

| 阶段 | 方案 | 结果 | 原因 |
|------|------|------|------|
| 初版 | LangChain4j `OpenAiChatModel` | ❌ | 与 `langchain4j 1.0.0-beta1` 兼容性问题 |
| 终版 | `RestClient` 直调 DeepSeek API | ✅ | 零额外依赖，与已验证的 demo 路径一致 |

**最终架构**：

```
LlmService (@Component)
  ├─ @Value("${wechat.ai.llm.api-key}")    
  ├─ @Value("${wechat.ai.llm.base-url}")    
  ├─ @Value("${wechat.ai.llm.model}")       
  ├─ RestClient.Builder (Spring 注入)        
  └─ ToolRegistry (@Lazy 注入)               
```

**请求体格式**（标准 OpenAI 兼容）：

```json
{
  "model": "deepseek-chat",
  "messages": [{"role": "system"}, {"role": "user"}],
  "tools": [{"type": "function", "function": {"name": "queryWeather", ...}}],
  "temperature": 0.7
}
```

**消息历史维护**：

```
首轮: messages = [system, user]
                    ↓ LLM → tool_calls
      messages = [system, user, assistant(tool_calls)]
      
次轮 (tool_execute 后):
      messages = [system, user, assistant(tool_calls), tool(result)]
                    ↓ LLM → 看到结果 → "南京阴，33°C"
      messages = [..., assistant("南京阴，33°C")]
```

**文档对应**: 接口文档 5.1 节（核心接口）、附录 D.6

### 里程碑 4：ToolExecuteNode 工具执行（上午）

**涉及文件**: `ToolExecuteNode.java`

**执行流程**：

```
ToolExecuteNode.apply(state)
  ├─ ① 读取 state 中的 toolExecutionRequests
  ├─ ② 遍历每个 tool call：
  │     ├─ 查找对应的 @Tool Bean
  │     ├─ 用 Jackson 解析参数 JSON → Java 类型
  │     ├─ 反射调用：method.invoke(bean, paramValues)
  │     ├─ 结果序列化为 JSON
  │     └─ 追加到 messageHistory：{role: "tool", content: 结果}
  └─ ③ 返回 {messageHistory, needTool: false}
```

**类型转换支持**：

| JSON 类型 | Java 类型 |
|-----------|----------|
| `string` | `String` |
| `integer` | `int` / `Integer` / `long` / `Long` |
| `number` | `double` / `Double` |
| `boolean` | `boolean` / `Boolean` |
| `array` | `List`（Jackson 反序列化） |

**文档对应**: 接口文档 6.2 节

### 里程碑 5：图编排调试（上午-下午，8 轮排错）

**涉及文件**: `ChatGraphConfig.java`（删除 `LlmConfig.java`）

**当前图结构**（简化版 `simpleChatGraph`）：

```
START → prepare_input → llm_think
                         ├─ needTool=true  → tool_execute → 回到 llm_think
                         └─ needTool=false → END → 回复用户
```

**调试问题完整记录**：

| # | 错误 | 根因 | 解决 |
|---|------|------|------|
| 1 | `The dependencies form a cycle: ToolController → toolRegistryImpl` | `ToolRegistryImpl` 注入 `ApplicationContext` + `ToolController` 注入 `ToolRegistry` 形成间接循环 | 类上加 `@Lazy` |
| 2 | `TODO: getOrCreateActiveSession` | `SessionServiceImpl` 是桩代码 | 跳过 `session_prepare` 节点 |
| 3 | `UnmodifiableMap.computeIfAbsent` | `state.data()` 返回不可修改 Map | 改为 `get()` + 判空 |
| 4 | `The dependencies form a cycle: llmService → toolRegistryImpl` | `LlmService` 注入 `ToolRegistry`，后者在初始化中 | `LlmService` 参数加 `@Lazy` + 配置 `spring.main.allow-circular-references=true` |
| 5 | `UnmodifiableMap.put` at LlmService:156 | `state.data().put()` 对不可修改 Map 写入 | 改由节点返回值传递 |
| 6 | `Messages with role 'tool' must be a response to a preceding message with 'tool_calls'` | `ToolExecuteNode` 返回 `messageHistory` 覆盖了上一轮的 `assistant(tool_calls)` | 两个节点都通过返回值传递 |
| 7 | `Maximum number of iterations (25) reached!` 死循环 | `LlmService` 没把 `assistant(tool_calls)` 加到 `messageHistory`，每轮都是 `[system, user]` | 补回 `messages.add(assistantMsg)` |
| 8 | 工具调用成功但回复不自然 | 提示词太简单 | 结构化 SYSTEM_PROMPT |

**LangGraph 状态管理注意事项**：

| 原则 | 说明 |
|------|------|
| `state.data()` 不可写 | 返回的是 `UnmodifiableMap`，只能通过节点返回值传递增量 |
| LangGraph 每次重建状态 | 对列表的原地修改会丢失，必须每次返回完整的 `messageHistory` |
| 消息链必须完整 | `assistant(tool_calls)` 和 `tool(result)` 都必须追加，缺一 DeepSeek 会拒接 |

### 里程碑 8：多轮对话记忆设计（下午）

**设计文档写入**: 接口文档 7.5 节

**方案**：`WechatServiceImpl` 中用 `ConcurrentHashMap` 按 userId 缓存 `messageHistory`。

```
用户发消息
  ├─ 从 userContexts.get(fromUser) 取历史
  ├─ 传入 initData → 图执行
  └─ 取回更新后的 messageHistory → userContexts.put(fromUser, ...)
```

**边界情况**：

| 场景 | 行为 |
|------|------|
| 首次对话 | 无历史，LlmService 自动建 `[system, user]` |
| 连续对话 | 历史累积，LLM 看到上下文 |
| 进程重启 | 清空，相当于首次对话 |
| 多用户 | ConcurrentHashMap 按 userId 隔离 |

**后续优化**（待实现）：

| 优化 | 说明 | 优先级 |
|------|------|--------|
| Redis 持久化 | 替代 ConcurrentHashMap，重启不丢失 | 高 |
| 消息上限 | 限制 50 轮，旧消息丢弃 | 中 |
| Token 控制 | 接近上限时自动摘要压缩 | 低 |

## 五、架构决策记录

### 5.1 放弃 LangChain4j ChatModel

- **决策时间**: 2026-07-17 上午
- **原因**: `OpenAiChatModel` 与 `langchain4j 1.0.0-beta1` 兼容性差，`baseUrl` 拼接逻辑与 DeepSeek 不匹配
- **替代方案**: 改用 `RestClient` 直调 DeepSeek /v1/chat/completions
- **保留**: `@Tool` 和 `@P` 注解仍保留，作为工具元数据标记

### 5.2 ToolRegistry 懒扫描

- **决策时间**: 2026-07-17 上午
- **原因**: @PostConstruct 扫描 ApplicationContext 导致 Bean 循环依赖
- **方案**: 改为 `synchronized` + `volatile` 懒初始化，第一次被调用时扫描
- **影响**: 工具扫描日志在第一次调图时打印，而非启动时

### 5.3 LangGraph 状态传递

- **决策时间**: 2026-07-17 下午
- **关键经验**: `state.data()` 返回 `UnmodifiableMap`，只能通过节点返回值传递增量
- **规则**: 复杂嵌套对象（如 `messageHistory`）每次都必须完整传回，不能依赖原地修改

### 5.4 循环引用配置

- **决策时间**: 2026-07-17 下午
- **配置**: `spring.main.allow-circular-references=true`
- **背景**: LlmService(→ToolRegistry→ApplicationContext ) 与 ToolRegistryImpl(→ApplicationContext) 间接循环，仅在启动时触发，运行后无影响
