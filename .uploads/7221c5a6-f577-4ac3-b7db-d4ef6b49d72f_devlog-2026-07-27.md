## 概述

今日完成多账号架构从设计到落地，将单 Bot 微信助手升级为支持多个 Bot 同时在线、独立登录、独立消息路由的多账号架构。**不涉及 agent 模块**，改动集中在 common / wechat / session 三层。

核心设计：每个 Bot 独立 `ILinkClient` + 独立心跳 + 独立消息路由。AI 上下文按 `conversationKey = clientId:fromUserId` 复合键隔离，Session/Remind 按 `(wechatClientId, userId)` 双键隔离。

| 阶段 | 内容 |
|:----:|------|
| Phase 1 | common 模块基础类型（WechatMessageContext、ConversationKey、ClientStatus） |
| Phase 2 | 多账号基础设施（WechatClientRegistry + 实现 + LoginStateStore + Caffeine） |
| Phase 3 | 消息全链路改造（Dispatcher→Handler→Bridge→Sender 适配 conversationKey） |
| Phase 4 | 数据层改造（session/remind 表 + wechat_client_id 列 + Mapper/Servcie 适配） |
| Phase 5 | Admin REST API + 配置 + 编译验证 |

## 三、Phase 3：消息全链路改造

### 改动策略

每个改造点遵循 `if (multiAccountEnabled) → 新路径 else → 旧路径` 模式，**单账号默认行为完全不变**。

### 条件装配（单账号 Bean 退位）

| 文件 | 改动 |
|------|------|
| `WechatConnectionManager.java` | +`@ConditionalOnProperty(enabled=false, matchIfMissing=true)` |
| `WechatLoginStore.java` | 同上 |
| `WechatMessageDispatcher.java` | 同上 |

多账号启用后，三个单账号 Bean 自动不被 Spring 加载，由 `WechatClientRegistryImpl` + `WechatLoginStateStoreImpl` + `WechatMessageEventListener` 接管。

### 适配方法（新增 ByKey 重载）

| 文件 | 新增方法 |
|------|---------|
| `WechatChatBridge.java` | `thinkByKey(conversationKey, ...)`, `thinkByKeyOnCurrentThread(...)` |
| `WechatInboundHandler.java` | `handleTextByKey`, `handleImageByKey`, `handleVoiceByKey`, `handleFileByKey` |
| `WechatOutboundSender.java` | `sendTextByKey`, `sendReplyByKey`, `sendErrorByKey`, `sendImageByKey` |

### 发送路由修复（踩坑）

`WechatOutboundSender` 在多账号模式下调用 `connectionManager.getClient()` 报 `NoSuchBeanDefinitionException`。

**修复**：添加 `getActiveClientForUser(userId)` 方法，通过 `WechatClientRegistry.findClientForUser(userId)` 查找用户对应的正确 Bot，实现精准发送路由。

### 消息流对比

```
Before (单账号):
  ILinkClient(单例) → WechatMessageDispatcher.dispatchMessages()
    → InboundHandler(fromUser) → ChatBridge(fromUser)
    → OutboundSender → connectionManager.getClient().sendText(fromUser)

After (多账号):
  ILinkClient(bot-1) → WechatInboundBatchEvent
  ILinkClient(bot-2) → WechatInboundBatchEvent
    → WechatMessageEventListener(@EventListener)
      → recordUserClient(fromUser → clientId)
      → InboundHandler.handleTextByKey(conversationKey)
        → ChatBridge.thinkByKey(conversationKey)
          → OutboundSender → getActiveClientForUser(fromUser) → 正确的 Bot
```

## 七、踩坑记录

| # | 问题 | 根因 | 解决 |
|:--:|------|------|------|
| 1 | `WechatInboundBatchEvent` 编译失败 | 放在 common 模块但依赖 iLink SDK 的 WeixinMessage（common 无此依赖） | 移到 wechat 模块的 event 包 |
| 2 | `NoSuchBeanDefinitionException: WechatConnectionManager` | 多账号模式下 ConnectionManager 被禁用，但 `WechatOutboundSender` 仍硬编码调用 | 添加 `getActiveClientForUser()` 方法，通过 userId→client 映射路由 |
| 3 | `ILinkException: missing latest context token` | `getActiveClient()` 始终返回第一个 client，但消息可能是另一个 Bot 收到的 | 在 `WechatMessageEventListener` 中记录 `userId → clientId` 映射，发送时查找正确 Bot |

## 十一、v2.23：提示词分层重构

### 动机

中央 SYSTEM_PROMPT 120 行，列了 20+ 个具体工具，但中央 LLM 实际只看到 2 个 Agent 工具。提示词与实际能力严重不匹配。

### 改动

| 层级 | 位置 | 改前 | 改后 |
|------|------|------|------|
| 中央 | `LlmService.java` | 120 行（浏览器规则 + 语音规则 + 20 工具 + 红线） | 15 行（意图路由 + 红线） |
| generalAgent | `AgentGraphRunner.java` | 简陋："你是 generalAgent，工具列表..." | 45 行（语音标记 + 浏览器规则 + 文档格式 + 截图规则 + 图片处理 + 红线） |
| taxiAgent | `AgentGraphRunner.java` | 简陋 | 22 行（查坐标→估价→下单→路线工作流 + 回复格式） |

- 中央只做意图路由，不关心工具细节
- 子 Agent 拿到工具白名单后，动态拼接"领域规则 + 工具列表"
- 新增 Agent（如高德）只需在 `buildAgentSystemPrompt()` 加一个 switch 分支
