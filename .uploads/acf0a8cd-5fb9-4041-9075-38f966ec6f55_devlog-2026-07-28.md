## 一、ReAct 超时看门狗

### 问题背景

系统存在三个卡死点：
1. **工具调用无超时**：MCP 工具（滴滴、猎聘）、本地 @Tool、子 Agent 调用全部同步阻塞，单个工具卡住（如浏览器 30s+）→ 整个 ReAct 循环卡死
2. **AgentGraphRunner 的 timeoutMs 是摆设**：参数传了但方法体里完全没用，`compiledGraph.invoke()` 同步阻塞到天荒地老
3. **用户线程单线程池**：`WechatChatBridge.getExecutor(userId)` 每人一个单线程，一次卡死 → 该用户后续消息全堵

### 三层超时设计

```
┌─ doThink() 总超时 90s ─────────────────────────────┐
│  超时 → sender.sendReply("处理超时，请稍后重试")     │
│                                                     │
│  ┌─ AgentGraphRunner.run() 30s ──────────────────┐ │
│  │  compiledGraph.invoke() 包 Future.get(30s)     │ │
│  │  超时 → AgentResult.fail("超时")               │ │
│  │                                                │ │
│  │  ┌─ ToolExecuteNode 单工具 60s ────────────┐  │ │
│  │  │  supplyAsync + orTimeout(60s)            │  │ │
│  │  │  超时 → error JSON → LLM 换策略          │  │ │
│  │  └──────────────────────────────────────────┘  │ │
│  └────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────┘
```

### 新增文件

| 文件 | 说明 |
|------|------|
| `RunWatchdog.java` | Cached 线程池 + `runWithTimeout(Callable)` / `runWithTimeout(Runnable)` 两个重载，封装 `Future.get(timeout)` 模式 |

### 修改文件

| 文件 | 改动 |
|------|------|
| `ToolExecuteNode.java` | 三个工具执行路径（Agent/MCP/本地）各包 `watchdog.runWithTimeout(..., toolTimeoutMs)`，超时注入 error JSON，消息序列完整（tool_call_id 对得上，不会 400） |
| `AgentGraphRunner.java` | `run()` 内 invoke+resume 循环整体包 `watchdog.runWithTimeout(..., timeoutMs)`，超时返回 `AgentResult.fail` |
| `WechatChatBridge.java` | `think()`/`thinkOnCurrentThread()` 经过 `doThinkWithTimeout()` 包总超时，超时发提示给用户并释放线程 |
| `ChatGraphConfig.java` | 传 `RunWatchdog` 参数给 `ToolExecuteNode` |

### 配置项

```properties
# 单次工具调用超时（毫秒），默认 30s
wechat.watchdog.tool-timeout-ms=60000
# Bridge 总超时（毫秒），默认 90s  
wechat.watchdog.bridge-timeout-ms=120000
```

### 设计决策

- 超时不会真 kill 底层连接（Java 无法强杀阻塞的 HTTP），但能**让 ReAct 循环继续**、**用户线程不占死**
- 不自动重试，WRITE 工具超时不会自动重来（防双发）
- 工具超时注入 `role=tool` 的 error JSON，和现有异常处理模式一致，不会导致 400

## 二、猎聘 MCP 接入

### 背景

猎聘官方开放了 MCP 内测服务（`liepin.com/mcp/server`），将求职核心能力（简历查询/编辑、职位搜索、一键投递）封装为标准 MCP 接口。相比 Playwright 浏览器自动化方案：
- 验证码：API 鉴权替代，不存在
- 表单填错：结构化参数替代 DOM 定位，不存在
- 反爬/封号：官方 API，不存在
- 每个网站适配：一个 MCP 覆盖猎聘全站

### 新增文件

| 文件 | 说明 |
|------|------|
| `LiepinMcpConfigProperties.java` | `@ConfigurationProperties(prefix="mcp.liepin")`，字段：enabled、credential、baseUrl、timeoutSeconds |
| `LiepinMcpSource.java` | 实现 `McpSource` 接口，JSON-RPC 2.0 over HTTP，认证 Header `x-user-token`，13 个工具 |

### 接入协议

- 认证：`x-user-token` Header（凭证从 `liepin.com/mcp/server` 生成）
- 端点：`https://open-agent.liepin.com/mcp/user`
- 传输：MCP Streamable HTTP（`Accept: application/json, text/event-stream`）
- WRITE 工具：`user-apply-job` 标记为 WRITE，走图中断确认流程

### 13 个猎聘工具

| 类别 | 工具 |
|------|------|
| 查询 | `my-resume` |
| 新增 | `add-edu-exp` `add-job-want` `add-project-exp` `add-work-exp` |
| 修改 | `modify-edu-exp` `modify-job-want` `modify-project-exp` `modify-resume-base-info` `modify-self-assess` `modify-work-exp` |
| 操作 | `user-search-job` `user-apply-job` |

### 配置项

```properties
mcp.liepin.enabled=false
mcp.liepin.credential=
mcp.liepin.base-url=https://open-agent.liepin.com/mcp/user
```

### 接入机制

```
McpClientManager 启动
  → 扫描所有 McpSource Bean
  → LiepinMcpSource.fetchTools() → tools/list → 13 个工具
  → McpToolBridge 注册到 ToolRegistry（标记 source=MCP:LIEPIN）
  → LLM 对话中即可调用
```

## 三、Agent 工具分配优化

### 改动

| 文件 | 改动 |
|------|------|
| `AgentToolRegistry.java` | 新增 `getLiepinTools()`（过滤 MCP:LIEPIN）、`getGeneralToolsWithLiepin()`（基础工具 + 猎聘） |
| `AgentToolRegistration.java` | generalAgent 描述追加"简历查询与编辑、职位搜索、职位投递" |
| `ToolExecuteNode.java` | generalAgent 路由改用 `getGeneralToolsWithLiepin()`，使 generalAgent 携带 13 个猎聘工具 |
| `AgentGraphRunner.java` | GENERAL_AGENT_PROMPT 新增求职工具使用引导：**API 优先于浏览器**、投递直接调工具（系统会自动确认，LLM 不再额外问） |

### 避免二次确认

猎聘 `user-apply-job` 已标记 WRITE → 系统级中断确认。prompt 中写"投递时直接调 user-apply-job，系统会自动确认，你不要再额外问"，防止 LLM 先文字确认一次、系统再弹一次。

## 五、jobAgent 独立拆分

猎聘工具从 generalAgent 拆出为独立 `jobAgent`，和 taxiAgent 同级：

| Agent | 工具来源 | 场景 |
|-------|----------|------|
| `generalAgent` | 本地 @Tool beans | 天气/翻译/浏览器/邮件/提醒 |
| `taxiAgent` | MCP:DIDI | 打车/路线/地点搜索 |
| `filesystemAgent` | MCP:FILESYSTEM | 文件读写/目录操作 |
| `jobAgent` | MCP:LIEPIN（13 工具） | 简历/职位搜索/投递 |

### 改动

- `AgentToolRegistry` — 删除 `getGeneralToolsWithLiepin()`，保留 `getLiepinTools()`
- `ToolExecuteNode` — switch 加 `jobAgent` 分支
- `AgentGraphRunner` — 新增 `JOB_AGENT_PROMPT`，generalAgent 去求职引导，switch 加 `jobAgent`
- `AgentToolRegistration` — 注册 `jobAgent`（`AGENT:Job`），generalAgent 描述去求职

### JOB_AGENT_PROMPT 要点

- 搜职位/查简历直接调 API，原样输出不美化
- 投递调 `user-apply-job`，系统自动确认，不再额外问

## 六、OkHttp 超时修复

DeepSeek 冷启动/大响应超过 okhttp 默认 10s 读超时，LLM 调用频繁 `SocketTimeoutException`。

- `LlmService.init()` 直接创建 `OkHttpClient`（connect 30s / read 120s / write 30s），挂到 `RestClient`
- `WebMvcConfig` 注册 `OkHttpClient.Builder` Bean（30s/120s/30s）

---

## 七、Filesystem MCP 超时诊断

`npx @modelcontextprotocol/server-filesystem` 首次下载超 20s → `StdioClientTransport` 默认超时断开。根因：npm 代理 `127.0.0.1:7890` 未启动导致 `ECONNREFUSED`。修复：`npm config delete proxy` + 关 registry 镜像 + `npm install -g`。
