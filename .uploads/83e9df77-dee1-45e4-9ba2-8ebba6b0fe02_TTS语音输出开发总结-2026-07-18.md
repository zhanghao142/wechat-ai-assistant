# 微信智能体助手 — TTS 语音输出开发总结

> **日期**: 2026-07-18  
> **最终方案**: 阿里云百炼 CosyVoice + DashScope SDK WebSocket

---

## 一、方案演进

| # | 方案 | 结果 | 原因 |
|:-:|:----|:----:|:-----|
| 1 | Edge TTS REST API（免费、免 Key） | ❌ 放弃 | 底层是 WebSocket，Java 直接调复杂，社区封装都是 Python/Node.js |
| 2 | 阿里云百炼 DashScope HTTP API | ❌ 401 | API Key 没开通 HTTP TTS 权限 |
| 3 | DashScope OpenAI 兼容端点（`/v1/audio/speech`） | ❌ 404 | 该路径在 dashscope 上不存在 |
| 4 | **DashScope SDK v1 WebSocket** | ✅ **合成成功** | 同步调用，稳定 |
| 5 | NLS 网关 HTTP（AppKey + AccessToken） | ❌ 放弃 | 音色路由 500、AccessToken 有时效性 |
| 6 | DashScope SDK v2 WebSocket | ❌ 放弃 | v1 已通，v2 构造器不同（参数多） |
| 7 | iLink SDK sendVoice 发语音气泡 | ❌ **不可用** | Bot 出站语音气泡协议限制 |
| 8 | **iLink SDK sendFile 发 MP3 文件** | ✅ **可用** | 用户收到 MP3 文件点开听 |

## 二、最终技术方案

### 依赖
```xml

    <exclusions>
        <exclusion>

            <artifactId>slf4j-api</artifactId>

        <exclusion>
            <groupId>org.slf4j</groupId>
            <artifactId>slf4j-simple</artifactId>
        </exclusion>
    </exclusions>
</dependency>
```

### 配置
```properties
# application.properties
tts.api-key=sk-xxx
tts.websocket-url=wss://ws-{workspaceId}.cn-beijing.maas.aliyuncs.com/api-ws/v1/inference
tts.model=cosyvoice-v3-plus
tts.voice=longanhuan
```

### 核心代码

**TtsService.java**（语音合成）：
```java
@Component
public class TtsService implements InitializingBean {

    @Value("${tts.api-key}")        private String apiKey;
    @Value("${tts.websocket-url}")  private String websocketUrl;
    @Value("${tts.model}")          private String modelName;
    @Value("${tts.voice}")          private String voiceName;

    @Override
    public void afterPropertiesSet() {
        Constants.apiKey = apiKey;
        Constants.baseWebsocketApiUrl = websocketUrl;
    }

    public byte[] synthesize(String text) {
        SpeechSynthesisParam param = SpeechSynthesisParam.builder()
                .apiKey(apiKey)
                .model(modelName)
                .voice(voiceName)
                .format(SpeechSynthesisAudioFormat.MP3_24000HZ_MONO_256KBPS)
                .build();
        SpeechSynthesizer synthesizer = new SpeechSynthesizer(param, null);
        ByteBuffer audioBuffer = synthesizer.call(text);
        byte[] audio = new byte[audioBuffer.remaining()];
        audioBuffer.get(audio);
        return audio;
    }
}
```

**WechatServiceImpl.java**（用户触发→发送）：
```java
// LlmService SYSTEM_PROMPT 中让 LLM 在回复末尾加 [VOICE]
// WechatServiceImpl 检测 [VOICE] 标记，触发语音输出

private void callAiEngine(...) {
    // ...
    String reply = state.getReply();
    boolean useVoice = reply.contains("[VOICE]");
    reply = reply.replace("[VOICE]", "").trim();
    
    if (useVoice) {
        byte[] audio = ttsService.synthesize(reply);
        if (audio != null && audio.length > 0) {
            client.sendText(fromUser, reply);  // 先发文字
            client.sendFile(fromUser, audio, "语音回复.mp3", "mp3");  // 再发 MP3 文件
        }
    } else {
        client.sendText(fromUser, reply);
    }
}
```

### 数据流
```
用户说"用语音回答" 
  → LLM 回复 "好的，今天天气不错\n[VOICE]"
  → callAiEngine 检测到 [VOICE]
  → 去掉 [VOICE] 标记剩 "好的，今天天气不错"
  → TtsService.synthesize("好的，今天天气不错")
  → DashScope WebSocket → CosyVoice 合成 → 返回 MP3 byte[]
  → client.sendText(用户, 文字)
  → client.sendFile(用户, MP3, "语音回复.mp3")
```

## 三、SDK 版本踩坑（v1 vs v2）

DashScope SDK 的 TTS 包有两套 API，在不同 package 下：

| 对比 | v1（最终选用） | v2 |
|:----|:--------------|:---|
| 包路径 | `com.alibaba.dashscope.audio.tts` | `com.alibaba.dashscope.audio.ttsv2` |
| 同步方式 | `new SpeechSynthesizer().call(param)` 同步 | `new SpeechSynthesizer(param, null).call(text)` 同步 |
| 参数构造 | `SpeechSynthesisParam.builder()` | `SpeechSynthesisParam.builder()` |
| voice 设置 | `.parameter("voice", name)` 或 `.voice(name)` | `.voice(name)` 直接 |
| format 设置 | 需在 builder 中 `.parameter("format", "mp3")` | 枚举 `SpeechSynthesisAudioFormat.MP3_24000HZ_MONO_256KBPS` |
| 构造器 | 无参构造 | 传入 `(SpeechSynthesisParam, null)` |
| 资源释放 | 不需要 | 需要 `getDuplexApi().close()` |
| 稳定性 | ✅ 稳定 | ✅ 稳定 |

**注意**：v2 的 `SpeechSynthesizer` 构造器必须传 `(param, null)`，否则 `call(text)` 会因父类 field 未初始化而 NPE。

## 四、坑与解决方法

### 4.1 API Key 权限问题

| 问题 | 说明 |
|:----|:------|
| `401 InvalidApiKey` | Key 格式不对或不在白名单 |
| `current user api does not support http call` | Key 没开通 HTTP 调用权限 |
| **最终方案** | DashScope SDK 走 WebSocket 协议，绕过了 HTTP 权限限制 |

### 4.2 WebSocket 配置

`Constants.apiKey` 和 `Constants.baseWebsocketApiUrl` 必须在调用前设置（静态变量），建议在 `InitializingBean.afterPropertiesSet()` 中设置。

注意：`Constants.baseWebsocketApiUrl` 是**全局静态变量**，多用户共享，但 WebSocket 连接各自独立，没问题。

### 4.3 音色名

| 模型 | 可用音色 | 不支持的音色 |
|:----|:--------|:-----------|
| cosyvoice-v1 | `longxiaochun`, `longanyang` | — |
| cosyvoice-v3-plus | `longanhuan`, `longanyang` 等 | `longxiaochun`, `xiaoyun` |

**报错特征**：
```
ROUTE_GROUP_NOT_FOUND: Route group 'tts-arena.XXX' not found!
```

### 4.4 v2 构造器 NPE

```java
// ❌ NPE
new SpeechSynthesizer(param, null).call(text);  
// 必须：SpeechSynthesizer(param, null) 或 SpeechSynthesizer() 然后 .call(param)

// ✅ v1 正确
new SpeechSynthesizer().call(param);

// ✅ v2 正确
SpeechSynthesisParam param = SpeechSynthesisParam.builder()
        .apiKey(apiKey).model(modelName).voice(voiceName)
        .format(SpeechSynthesisAudioFormat.MP3_24000HZ_MONO_256KBPS)
        .build();
new SpeechSynthesizer(param, null).call(text);
```

### 4.5 LLM 不按格式加 [VOICE]

**问题**：DeepSeek 不一定会严格按照 SYSTEM_PROMPT 的格式在末尾加 `[VOICE]`，有时放在中间，有时不加。

**解决**：代码层面冗余判断，不用 `endsWith` 用 `contains`：
```java
boolean useVoice = reply.contains("[VOICE]");
reply = reply.replace("[VOICE]", "").trim();
```

### 4.6 Maven 依赖冲突

DashScope SDK 自带 slf4j-simple，与 Spring Boot 的 slf4j 冲突：
```xml
<exclusions>
    <exclusion>
        <groupId>org.slf4j</groupId>
        <artifactId>slf4j-api</artifactId>
    </exclusion>
    <exclusion>
        <groupId>org.slf4j</groupId>
        <artifactId>slf4j-simple</artifactId>
    </exclusion>
</exclusions>
```

### 4.7 WebSocket 资源释放

每次 `synthesize()` 调用后，必须关闭 WebSocket 连接，否则连接泄漏：

```java
finally {
    if (synthesizer != null) {
        try { synthesizer.getDuplexApi().close(1000, "bye"); } catch (Exception ignored) {}
    }
}
```

## 五、⚠️ 未解决：语音气泡不可用

### 问题描述
TTS 合成成功、`sendVoice` 调用成功（无异常）、但接收方微信看不到语音气泡。

### 表现
```
日志：
【TTS】合成完成 (2358ms): 19 字符 → 73243 字节
[微信语音回复] xxx: 好的，知道啦 (22s)

手机微信：无语音气泡，无任何显示
```

### 根因分析
1. **iLink Bot 出站语音受协议限制**：社区反馈 Bot 发的语音消息接收方不再渲染语音气泡
2. **SILK 格式问题**：`sendVoice` 内部调用 `uploadVoice` 上传到微信 CDN，但发给接收方时标记 `encode_type=6`（SILK），实际传的是 MP3 → 客户端解码失败
3. **长参数 `sendVoice`（9 参数）可以调但效果未知**：可指定 encode_type=7（MP3），测试结论相同 → 无气泡

### 当前处理
```java
// 改为 sendFile 发 MP3 附件
client.sendText(fromUser, reply);
client.sendFile(fromUser, audio, "语音回复.mp3", "mp3");
```

用户看到文字回复 + 收到 MP3 文件消息，点开即可播放。

### 尝试过的其他方向

| 方向 | 结果 | 说明 |
|:----|:----:|:-----|
| SILK 编码 | ❌ | 纯 Java SILK 库不存在（Maven 上无可用包） |
| ffmpeg 转码 SILK | ⏳ | 本地可行，但组员需装 ffmpeg |
| cc.imorning:silk | ❌ | Android JNI 库，不能用于服务端 |
| silk4j | ❌ | 同上 |
| sendVoice 长参数（encode_type=7） | ❌ | 还是无气泡 |

### 后续建议
- 等待 iLink SDK 更新或微信协议放宽
- 如有组员用过 iLink 发语音成功，分享经验
- 可考虑社区版微信机器人（如 Wechaty），但需要换接入层

## 六、调用链路完整示意图

```
用户 → "说给我听"
  │
  ▼
WechatServiceImpl.handleItem()
  │ type=3 语音 → VoiceItem.getText() → 拼文字
  ▼
callAiEngine()
  │ 投递到用户线程池
  ▼
LlmService.think() → DeepSeek API
  │
  ▼ 回复 "好的，今天天气不错\n[VOICE]"
  │
  ├─ contains("[VOICE]")? → true
  │
  ├─ reply = "好的，今天天气不错"
  │
  ├─ TtsService.synthesize(reply)
  │     │
  │     ├─ afterPropertiesSet: Constants.apiKey + Constants.baseWebsocketApiUrl
  │     ├─ SpeechSynthesisParam.builder()
  │     │     .apiKey(apiKey)
  │     │     .model("cosyvoice-v3-plus")
  │     │     .voice("longanhuan")
  │     │     .format(MP3_24000HZ_MONO_256KBPS)
  │     │     .build()
  │     ├─ new SpeechSynthesizer(param, null)
  │     ├─ synthesizer.call(text) → WebSocket → CosyVoice → MP3
  │     └─ return MP3 byte[]
  │
  ├─ client.sendText(fromUser, reply)      → 文字回复 ✅
  └─ client.sendFile(fromUser, mp3, ...)   → MP3 文件 ✅
```
