# 天气助手项目 — 微信 Bot 多用户同时交流实现详解

> ⚠ **文档定位（2026-08-03）**：本文描述的是早期**天气助手 / iLink 多 Bot 二维码**方案，供对照参考。  
> 当前 306 工程的微信多账号请看 `wechat-ai-assistant-api.md` §7.3（`WechatClientRegistry`）；  
> 桌面邮箱登录请看 **`桌面邮箱登录实现详解.md`**（`/api/v1/mail` + `app_user`）。

## 一、概述

本项目通过微信 iLink SDK 实现 Bot 功能。核心需求是：**同时生成多个微信二维码，不同用户扫描不同二维码后，Bot 能同时与多个微信用户独立交流，互不干扰。**

---

## 二、多用户的两层含义

本项目的"多用户"有两层：

| 层级 | 含义 | 实现方式 |
|------|------|----------|
| **Bot 实例级** | 启动多个 Bot 账号，每个 Bot 生成独立二维码 | `bot -c N` 启动 N 个线程，每个线程一个 ILinkClient |
| **微信用户级** | 同一个 Bot 账号下，多个微信用户同时发消息 | 每个微信用户的 `from_user_id` 不同，数据库按 userId 隔离 |

---

## 三、多 Bot 实例 + 多二维码的启动流程

### 3.1 入口：Bot.java

文件：`commands/Bot.java`

```java
@Option(names = {"-c", "--count"}, description = "同时启动的 Bot 数量，每个生成独立二维码，默认 1")
private int count = 1;

@Option(names = {"-n", "--name"}, description = "Bot 名称前缀，用于区分多实例")
private String name;

public Integer call() {
    List<IlinkBotService> bots = new ArrayList<>();
    List<Thread> threads = new ArrayList<>();

    for (int i = 1; i <= count; i++) {
        final int index = i;

        // 每个实例有独立名称，如 bot1、bot2 或自定义前缀 mybot-1、mybot-2
        String botName;
        if (name != null && !name.isBlank()) {
            botName = count > 1 ? name + "-" + i : name;
        } else {
            botName = count > 1 ? "bot" + i : null;
        }

        // 每个 Bot 实例创建独立的 WeatherService 和 IlinkBotService
        WeatherService weatherService = new WeatherService();
        IlinkBotService botService = new IlinkBotService(weatherService, botName);
        bots.add(botService);

        // 每个 Bot 跑在独立线程中
        Thread t = new Thread(() -> {
            botService.start();   // 扫码登录 → 长轮询收消息 → 回复
        }, "bot-" + botName);
        threads.add(t);
    }

    // 逐个启动线程，间隔 3 秒避免 SDK 并发冲突
    for (Thread t : threads) {
        t.start();
        Thread.sleep(3000);
    }
    // ...
}
```

### 3.2 每个 Bot 实例拥有独立的登录态文件

文件：`service/IlinkBotService.java:57-60`

```java
public IlinkBotService(WeatherService weatherService, String botName) {
    // ...
    String fileName = (botName != null && !botName.isBlank())
            ? ".ilink_session_" + botName + ".json"   // 如 .ilink_session_bot1.json
            : ".ilink_session.json";                   // 默认

    // ...

```

每个 Bot 实例的登录态保存到独立文件，互不覆盖。

### 3.3 每个 Bot 实例拥有独立的 ILinkClient

```java
this.client = ILinkClient.builder()
        .config(ILinkConfig.builder()
                .connectTimeoutMs(35000)
                .readTimeoutMs(35000)
                .loginTimeoutMs(300_000)        // 5分钟登录超时
                .heartbeatEnabled(true)
                .heartbeatIntervalMs(60_000)     // 1分钟心跳
                .autoReconnectEnabled(true)      // 自动重连
                .reconnectMaxAttempts(Integer.MAX_VALUE)
                .build())
        .onLogin(...)      // 登录成功/失败回调
        .onDisconnect(...)  // 断连/重连回调
        .build();
```

每个 Bot 实例在构造时就创建了自己独立的 `ILinkClient`，拥有独立的网络连接、心跳、重连机制。

## 四、多二维码同时生成的完整流程

执行 `weather bot -c 3` 后的时序：

```
主线程
  │
  ├─ 创建 IlinkBotService(botName="bot1")
  │    └─ 内部: new ILinkClient() → 独立的 client 实例
  │    └─ sessionFile = ".ilink_session_bot1.json"
  │
  ├─ 创建 IlinkBotService(botName="bot2")
  │    └─ 内部: new ILinkClient() → 独立的 client 实例
  │    └─ sessionFile = ".ilink_session_bot2.json"
  │
  ├─ 创建 IlinkBotService(botName="bot3")
  │    └─ 内部: new ILinkClient() → 独立的 client 实例
  │    └─ sessionFile = ".ilink_session_bot3.json"
  │
  ├─ Thread-1.start()  →  bot1.start()
  │    └─ doLogin() → client.executeLogin() → 生成二维码URL #1 → 打印到控制台
  │    └─ 等待扫码 → client.getLoginFuture().get()
  │    └─ 登录成功 → saveSession() → 写入 .ilink_session_bot1.json
  │    └─ 进入消息循环: while(true) { getUpdates() → processMessage() }
  │
  ├─ sleep(3000)  // 错开 3 秒
  │
  ├─ Thread-2.start()  →  bot2.start()
  │    └─ doLogin() → client.executeLogin() → 生成二维码URL #2 → 打印到控制台
  │    └─ ...（同上）
  │
  ├─ sleep(3000)
  │
  ├─ Thread-3.start()  →  bot3.start()
  │    └─ doLogin() → client.executeLogin() → 生成二维码URL #3 → 打印到控制台
  │    └─ ...（同上）
  │
  └─ 主线程阻塞在 t.join()，等待所有 Bot 线程结束
```

## 五、每个 Bot 内部的多微信用户并发处理

即使只有一个 Bot 实例，也能同时服务多个微信用户。关键在 `processMessage` 方法：

### 5.1 消息接收：长轮询 + 线程池并发

```java
public void start() throws Exception {
    doLogin();
    while (!Thread.currentThread().isInterrupted()) {
        List<WeixinMessage> messages = client.getUpdates();  // 长轮询，一次可能返回多条消息
        for (WeixinMessage msg : messages) {
            executor.submit(() -> processMessage(msg));      // 每条消息提交到线程池并发处理
        }
    }
}
```

`executor` 是 `Executors.newCachedThreadPool()`，不同微信用户的消息在独立线程中并发处理。

### 5.2 用户识别：from_user_id

```java
private void processMessage(WeixinMessage msg) {
    String userId = msg.getFrom_user_id();  // 每个微信用户有唯一 ID
    // ...
}
```

微信的 `from_user_id` 是每个微信用户相对于该 Bot 的唯一标识。同一个 Bot 下，用户甲和用户乙的 `from_user_id` 不同。

### 5.3 回复精准投递

```java
// 回复文本给指定用户
client.sendText(userId, text);

// 回复图片给指定用户
client.sendImage(userId, imgBytes, "weather.png", null);

// 回复文件给指定用户
client.sendFile(userId, fileData, filename, null);
```

所有回复方法都传入 `userId`，iLink SDK 内部根据 userId 将消息路由到正确的微信用户。

## 六、多用户数据隔离

所有 Bot 实例共享同一个 H2 数据库（`data/chat_history.mv.db`），但数据按 userId 隔离。

### 6.1 数据库表结构

**chat_history 表** — 对话历史（7 天自动过期）：

```sql
CREATE TABLE chat_history (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    session_id VARCHAR(128) NOT NULL,   -- 即 userId，隔离关键
    role VARCHAR(20) NOT NULL,          -- system / user / assistant / tool
    content CLOB,
    tool_calls CLOB,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

**user_memory 表** — 用户永久记忆（不受 7 天 TTL 影响）：

```sql
CREATE TABLE user_memory (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id VARCHAR(128) NOT NULL,
    memory_key VARCHAR(128) NOT NULL,
    memory_value CLOB NOT NULL,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### 6.2 按 userId 读写

所有 SQL 操作都带 `session_id` / `user_id` 条件：

```java
// 加载用户对话历史
public List<ChatMessage> getMessages(String sessionId) {
    sql = "SELECT ... FROM chat_history WHERE session_id = ? ORDER BY created_at ASC";
}

// 保存消息
public void addMessage(String sessionId, ChatMessage msg) {
    sql = "INSERT INTO chat_history (session_id, role, content, ...) VALUES (?, ?, ?, ...)";
}

// 保存永久记忆
public void setMemory(String userId, String key, String value) {
    sql = "MERGE INTO user_memory (user_id, memory_key, memory_value, ...) KEY(user_id, memory_key) ...";
}
```

## 七、LLM 层的用户隔离

文件：`service/LlmService.java`

```java
public void chatStream(String userId, String message, StreamCallback callback) {
    // 1. 从数据库加载该用户的完整对话历史
    List<ChatMessage> history = sessionStore.getMessages(userId);

    // 2. 首次对话：注入 system prompt + 该用户的永久记忆
    if (history.isEmpty()) {
        String fullPrompt = buildSystemPrompt(userId);
        // buildSystemPrompt 内部：
        //   Map<String, String> memories = sessionStore.getAllMemories(userId);
        //   将记忆拼入 prompt，如 "姓名: 张三\n偏好: 爱吃辣"
        ChatMessage sysMsg = new ChatMessage("system", fullPrompt);
        history.add(sysMsg);
        sessionStore.addMessage(userId, sysMsg);
    }

    // 3. 追加用户消息 → 持久化
    history.add(userMsg);
    sessionStore.addMessage(userId, userMsg);

    // 4. 调用 LLM API → Function Calling 递归 → 每条 assistant/tool 消息都持久化
    runConversationStream(userId, history, ...);
}
```

每个 userId 拥有独立的对话上下文，LLM 看到的只是"这一个用户的完整历史"，不知道其他用户的存在。

## 九、关键设计要点总结

| 设计点 | 实现方式 |
|--------|----------|
| **多个二维码** | `bot -c N` 启动 N 个线程，每个线程独立 `ILinkClient`，各自调用 `executeLogin()` 生成独立二维码 |
| **登录态隔离** | 每个 Bot 实例独立的 `.ilink_session_botN.json` 文件 |
| **扫码后同时在线** | 所有 Bot 线程同时运行 `while(true) { getUpdates() }` 消息循环 |
| **微信用户识别** | `msg.getFrom_user_id()` 获取微信用户唯一标识 |
| **并发处理** | `CachedThreadPool`，不同用户消息在独立线程中处理 |
| **对话隔离** | H2 数据库按 `session_id`（即 userId）分区，所有 SQL 带 WHERE 条件 |
| **记忆隔离** | `user_memory` 表按 `user_id` 分区，首次对话自动注入该用户的记忆 |
| **回复投递** | `client.sendText(userId, ...)` 按 userId 精准回复 |
| **LLM 上下文隔离** | 每个 userId 独立加载历史 → 独立调用 LLM API，互不干扰 |
