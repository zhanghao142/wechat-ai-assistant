## 1. 方案变更说明

### v1.0 → v2.0 对比

| 维度 | v1.0（已废弃） | v2.0（当前方案） |
|------|---------------|----------------|
| 识别引擎 | Tesseract OCR（纯文字识别） | Qwen-VL / GLM-4V 等多模态 LLM |
| 识别能力 | 仅识别图片中的**文字** | 识别图片中的**物体/场景/人物/文字** |
| 存储 | 本地磁盘 + MySQL + Redis 队列 | **不需要**，仅缓存到内存 |
| 异步处理 | Worker 消费 Redis 队列 | **同步直接等**，0 额外组件 |
| 额外依赖 | Tesseract 本地引擎 + Tess4J | 多模态 LLM API（一个 HTTP 调用） |
| 维护成本 | 多一套基础设施 | **零维护** |

### 为什么改方案

上一版是为"仅识别图片中的文字（OCR）"设计的，涉及装 Tesseract OCR 引擎 + 下载中文包 + 管理训练数据 + 建 MySQL 表 + 搭 Redis 队列 + 写 Worker。对于需要**识别物体/场景/人物**的需求来说太重了。

多模态 LLM 方案直接用大模型理解图片，**跟调 DeepSeek 一样简单**，且 LLM 真正"看懂"图片内容，能回答"猫在沙发上做什么"这类问题，而不是只返回标签。

## 2. 技术选型：为什么用多模态 LLM

### 2.1 选型对比

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|:----:|
| **Qwen-VL（多模态 LLM）** | 零额外依赖、中文好、不限识别类别、天然理解上下文 | 需要 API 额度、依赖网络 | ✅ **推荐** |
| Tesseract OCR | 离线免费 | 只能认字、需要装引擎 + 中文包 | ❌ 能力不足 |
| DJL / YOLO | 免费离线、Java 生态 | 首次下载模型 100MB+、识别类别有限 | ❌ 不够灵活 |
| 百度云/阿里云图像识别 | 专业化、准确率高 | 收费、有些已停服 | ❌ 要钱或已停 |

### 2.2 多模态 LLM 对比

| 模型 | 厂商 | 接入方式 | 免费情况 |
|------|------|---------|---------|
| **Qwen-VL-Plus** | 通义千问 | REST API | 新用户送额度，有免费档 |
| **Qwen-VL-Max** | 通义千问 | REST API | 同上，精度更高 |
| **GLM-4V** | 智谱 | REST API | 注册送额度 |
| **deepseek-vl2** | DeepSeek | REST API | 按量计费 |

**推荐 Qwen-VL-Plus**：国内网络好、中文识别强、跟你现有的 DeepSeek 调用方式完全一样。

## 3. 整体数据流

### 3.1 完整链路（当前架构）

```
微信用户
  │  发送图片
  ▼
WechatServiceImpl.handleMessages()
  │  遍历 item_list → item.type == 2 → 图片消息
  │
  ├─ client.downloadImageFromMessageItem(item) → byte[]
  │
  ├─ QwenVLService.recognize(imageBytes) → "一只橘猫坐在灰色沙发上"
  │     │  HTTP POST → https://dashscope.aliyuncs.com/.../chat/completions
  │     │  消息格式：text + base64 image_url
  │     ▼  多模态 LLM 返回描述
  │
  ├─ 把识别结果拼成消息内容：
  │   "[用户发送了一张图片，图片内容：一只橘猫坐在灰色沙发上]"
  │
  ├─ graph.invoke() → LLM 直接在上下文中看到图片内容
  │
  └─ client.sendText(fromUser, "这是一张猫咪的照片...")
       回复用户
```

### 3.2 不做的事（对比 v1.0）

| ❌ 不做 | 原因 |
|---------|------|
| 存本地磁盘 | 识别后不需要原始文件 |
| MySQL document 表 | 图片不需要跨会话持久化 |
| Redis 队列 + Worker | 没有异步任务，同步处理即可 |
| Tesseract + Tess4J 依赖 | 多模态 LLM 代替 OCR |
| SearchDocumentTool 搜索图片 | 图片内容在上下文里，不需要索引 |

### 3.3 文本消息流程（不变）

```
微信文字 → handleMessages() 检测 type==1
  → 提取 text_item.text
  → graph.invoke() → LLM 回复
  → 更新 userContexts（多轮记忆）
```

## 7. 代码实现要点

### 7.1 QwenVLService.java（新建）

```java
package com.wechatai.ai.ai;

import com.fasterxml.jackson.databind.JsonNode;
import com.fasterxml.jackson.databind.ObjectMapper;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.http.MediaType;
import org.springframework.stereotype.Component;
import org.springframework.web.client.RestClient;

import java.util.Base64;
import java.util.List;
import java.util.Map;

/**
 * 多模态 LLM 封装 — 调用 Qwen-VL 识别图片内容。
 * <p>
 * 接收图片 byte[]，返回图片的中文文字描述。
 * 与 LlmService（调 DeepSeek）使用相同的 RestClient 模式。
 */
@Component
public class QwenVLService {

    private static final Logger log = LoggerFactory.getLogger(QwenVLService.class);

    private static final String PROMPT = "请用简洁的语言描述这张图片中的内容，包括物体、场景、人物、动作等。控制在50字以内。";

    @Value("${qwen-vl.api-key}")
    private String apiKey;

    @Value("${qwen-vl.base-url}")
    private String baseUrl;

    @Value("${qwen-vl.model:qwen-vl-plus}")
    private String modelName;

    private final RestClient restClient;
    private final ObjectMapper objectMapper;

    public QwenVLService(RestClient.Builder restClientBuilder) {
        this.restClient = restClientBuilder.build();
        this.objectMapper = new ObjectMapper();
    }

    /**
     * 识别图片内容。
     *
     * @param imageBytes 原始图片数据（由 iLink SDK 下载并解密）
     * @return 图片的中文描述，如："一只橘猫坐在灰色沙发上"
     */
    public String recognize(byte[] imageBytes) {
        long start = System.currentTimeMillis();
        try {
            // ① 图片转 base64
            // imageBytes 可能是 JPG/PNG/BMP，统一按 JPEG 编码发送
            String base64 = Base64.getEncoder().encodeToString(imageBytes);

            // ② 构建请求体（多模态消息格式：text + image_url）
            Map<String, Object> requestBody = Map.of(
                    "model", modelName,
                    "messages", List.of(Map.of(
                            "role", "user",
                            "content", List.of(
                                    Map.of("type", "text", "text", PROMPT),
                                    Map.of("type", "image_url",
                                            "image_url", Map.of("url", "data:image/jpeg;base64," + base64))
                            )
                    )),
                    "max_tokens", 300
            );

            // ③ 调用 Qwen-VL API（跟调 DeepSeek 一样）
            String responseBody = restClient.post()
                    .uri(baseUrl)
                    .header("Authorization", "Bearer " + apiKey)
                    .contentType(MediaType.APPLICATION_JSON)
                    .body(requestBody)
                    .retrieve()
                    .body(String.class);

            // ④ 解析返回结果
            JsonNode root = objectMapper.readTree(responseBody);
            String content = root.path("choices").get(0)
                    .path("message").path("content").asText("");

            long elapsed = System.currentTimeMillis() - start;
            log.info("【Qwen-VL】识别完成 ({}ms): {}", elapsed, content);

            return content != null && !content.isEmpty() ? content.trim() : "[图片内容无法识别]";

        } catch (Exception e) {
            log.error("【Qwen-VL】识别失败", e);
            return "[图片识别服务暂时不可用]";
        }
    }
}
```

**改动点 2：`handleMessages` 重构为类型分发**

```java
private void handleMessages(List<WeixinMessage> messages) {
    for (WeixinMessage msg : messages) {
        String fromUser = msg.getFrom_user_id();
        if (msg.getItem_list() == null || msg.getItem_list().isEmpty()) {
            continue;
        }
        // 遍历 item_list，每个 item 独立处理
        for (MessageItem item : msg.getItem_list()) {
            handleItem(fromUser, item);
        }
    }
}
```

**改动点 3：`handleItem` 按 type 分发**

```java
private void handleItem(String fromUser, MessageItem item) {
    try {
        switch (item.getType()) {
            case 1: // 文本消息
                if (item.getText_item() != null) {
                    handleTextMessage(fromUser, item.getText_item().getText());
                }
                break;
            case 2: // 图片消息
                if (item.getImage_item() != null) {
                    handleImageMessage(fromUser, item);
                }
                break;
            case 4: // 文件消息（预留）
                log.info("文件消息暂不处理: {}", fromUser);
                break;
            default:
                log.debug("未知消息类型: type={}", item.getType());
        }
    } catch (Exception e) {
        log.error("处理消息失败 fromUser={}", fromUser, e);
        try {
            client.sendText(fromUser, "抱歉，处理出错了，请稍后再试");
        } catch (Exception ignored) {}
    }
}
```

**改动点 4：`handleTextMessage`（提取自现有逻辑）**

```java
private void handleTextMessage(String fromUser, String content) {
    if (content == null || content.isEmpty()) return;
    log.info("[微信消息] {}: {}", fromUser, content);
    callAiEngine(fromUser, content, "TEXT");
}
```

**改动点 5：`handleImageMessage`（新增）**

```java
private void handleImageMessage(String fromUser, MessageItem item) {
    log.info("[微信图片] {}: 正在识别图片...", fromUser);
    // ① 下载图片
    byte[] imageBytes = client.downloadImageFromMessageItem(item);
    // ② 同步调 Qwen-VL 识别
    String description = qwenVLService.recognize(imageBytes);
    // ③ 把识别结果拼成消息内容
    String content = "[用户发送了一张图片，图片内容：" + description + "]";
    log.info("[微信图片] {}: 识别结果 -> {}", fromUser, description);
    // ④ 走 AI 引擎
    callAiEngine(fromUser, content, "IMAGE");
}
```

**改动点 6：提取 `callAiEngine`（消除重复代码）**

```java
private void callAiEngine(String fromUser, String content, String messageType) {
    try {
        Map<String, Object> initData = new HashMap<>();
        initData.put(ChatGraphState.KEY_USER_ID, fromUser);
        initData.put(ChatGraphState.KEY_USER_MESSAGE, content);
        initData.put(ChatGraphState.KEY_MESSAGE_TYPE, messageType);
        initData.put("messageHistory", userContexts.get(fromUser));

        ChatGraphState state = chatGraph.compile()
                .invoke(initData)
                .orElseThrow(() -> new RuntimeException("图执行无返回"));

        // 更新多轮对话记忆
        Object updatedHistory = state.data().get("messageHistory");
        if (updatedHistory instanceof List) {
            userContexts.put(fromUser, (List<Map<String, Object>>) updatedHistory);
        }

        String reply = state.getReply();
        if (reply != null && !reply.isEmpty()) {
            client.sendText(fromUser, reply);
            log.info("[微信回复] {}: {}", fromUser, reply);
        }

    } catch (Exception e) {
        log.error("AI 处理失败 fromUser={}", fromUser, e);
        try {
            client.sendText(fromUser, "抱歉，处理出错了，请稍后再试");
        } catch (Exception ex) {
            log.error("发送错误消息失败", ex);
        }
    }
}
```

## 8. 常见问题与注意事项

### 8.1 图片大小

| 项目 | 说明 |
|------|------|
| 对端发来的图片原始 byte[] | 通常几十 KB ~ 几百 KB |
| base64 编码后 | 扩大约 1/3 |
| Qwen-VL 限制 | 图片最大 20MB（远用不到） |

### 8.2 性能

| 阶段 | 耗时 |
|------|------|
| iLink 下载解密 | ~200ms |
| Qwen-VL 识别 | 1-3s |
| AI 引擎处理 | 1-3s |
| **总耗时** | **约 3-7s** |

微信场景下这个耗时是可接受的。如果后续觉得慢，可以改为"先回'正在识别'，异步识别后推送结果"。

### 8.3 限额

Qwen-VL-Plus 免费额度用完后按 token 计费，图片按图片大小折算 token：
- 一张普通手机照片约 800-2000 token
- 比纯文本对话贵一些，但远低于专业图像识别 API

### 8.4 注意事项

| 注意点 | 说明 |
|--------|------|
| **不要用顶层 `message_type`** | 必须用 `item.getType() == 2` 判断图片消息 |
| **base64 编码** | 图片 byte[] 直接 base64，不需要先存临时文件 |
| **多轮记忆不受影响** | 图片识别结果以文本形式进入 messageHistory，天然持久 |
| **重启后图片丢失** | 图片识别结果在内存中，重启即丢失。但在微信对话里用户重发即可 |
| **同一张图重复问** | 用户发多张图时每个都独立识别并存入 messageHistory，LLM 能区分 |
| **Qwen-VL 不可用时** | 返回 `[图片识别服务暂时不可用]`，LLM 会如实告诉用户 |
| **LLM 不要主动复述图片** | 必须在 LlmService 的 SYSTEM_PROMPT 中加红线：`❌ 不要主动复述或描述图片内容，除非用户明确问"图片里有什么"`。否则 LLM 每次回复都会先描述一遍"我看到图片里有…"，影响对话体验 |

### 8.5 若 LLM 总是主动描述图片内容

如果遇到 LLM 回复时总爱先啰嗦"我看到图片里有……"再回答问题，需要在 **LlmService.java** 的 `SYSTEM_PROMPT` 回复红线中加一条规则：

```java
❌ 不要主动复述或描述图片内容，除非用户明确问"图片里有什么"
```

这条规则让 LLM 把图片内容当成**背景知识**，而不是"需要报告给用户的新信息"。
